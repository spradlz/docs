## How the schedule is worked

- **THE VERIFY FLEET** — Built-and-wired-but-never-walked items are a queue, not a mountain. Walk-lanes pull them straight off the registry proof bits, walk each in real Chrome, file the ten-field receipt, flip the bit. An item that fails its walk is an honest red and moves to the build pile with the failure named.
- **THE DAILY DECISION DIGEST** — Every open Zach decision reaches him as a yes/no with the evidence and a recommended default, batched into one page a day. A decision nobody surfaced properly is a lane blocked for days; a decision in the digest is thirty seconds.
- **THE BUILD CONVEYOR** — Builds run in dependency order, easiest wins first. A UI item passes the WIREFRAME GATE first - no locked HTML means it goes to the wireframe factory before it goes to a builder, then ships as a verbatim port. Never prose-built.
- **THE NAMED CRITICAL PATHS** — A named path never waits in the general queue. Both current paths (BETA-50 and the past-client pour) are held behind the robustness gate above.
