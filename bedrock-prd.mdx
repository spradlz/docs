## The one sentence

HouseLoop CRM's backend gets rebuilt from the ground up — correctly, once — while every screen, spec,
and intended function Zach designed is preserved. No feature shipped until the foundation passed the
40-lead proof on Zach's own phone and eyes — **it passed 8/11, and the laws it established stay.**

## The six signed decisions

1. **One master estate; teams are seats.** HouseLoop owns every person and lead forever. Teams get
   routing and visibility. If a team leaves, the leads don't leave.
2. **The integration layer is first-class and multi-adapter.** FUB is the permanent Zillow conduit for
   the 49k book; a future Zillow-direct API is a second adapter. Zillow is the source; FUB is a pipe.
3. **Raw tape → staging → import.** The fub.* mirror is a verbatim tape, never edited. One staging
   layer classifies every raw event once (correct kind, actor, source). The FUB slice of history is
   always re-derivable, shadow-first, swap only on Zach's sign. Native rows are sacred.
4. **Notifications are per-seat rules** keyed to catalog kinds, evaluated in one place, actor excluded.
5. **The whole 49k book, phased:** ~40 signal leads prove the machine → past clients → the full book.
   The 23 FUB trigger toggles remain the crossover gate.
6. **Full freeze** until the foundation is proven. All hands.

Amendments: **A1** the lifeline (inbound lead texts/calls notify + outbound texting works during the
freeze; everything else quiet) · **A2** it's the **Activity Log**, not the run log · **A3** the
artifact → board → Command Center pipeline is law · **A4** boards carry priority order + this master
checklist exists.

## The five layers

**Tapes** (raw capture, never edited) → **Staging** (one adapter per source, classified once,
re-runnable) → **The core** (people + the activity log + domain tables + the catalog as vocabulary
only, ONE write door) → **Reactions** (per-seat notification rules + configurable automation
triggers) → **Projections** (every surface renders through the one resolver).

## How the loop runs

The checklist board carries every item with a **permanent number**. The green active section is what's
being worked right now. Agents run `/board loop`: build → walk in Playwright → ten-field audit receipt
→ item goes green with its date → board republishes. Nothing is ticked without a receipt; a new
activity kind cannot ship without a harness walk. Zach reads
[Board #2](https://crm.houseloop.ai/boards/bedrock-checklist) at any moment to see exactly where the
rebuild is. **As of the 8/12 promote the board carries 127 items — 77 done, 20 active, 30 queued.**
The board is the live count; this number is a snapshot of the last promote, never the authority.
