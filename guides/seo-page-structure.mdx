## The stack (the geo lock, 2026-09-09)

The wireframe is the truth: `docs/wireframes/geo-page-LOCKED-2026-09-09.html`, pinned from the seo-revamp
board §6. "The home page, county, city, zip, neighborhood and every facet page are the same page. Only the
H1, the counts and the tail's scope change."

A geo route is a thin shell over the shared `SearchResultsPage`. Below the grid and the pagination,
`components/geo/LocationSeo.tsx` resolves the location once and composes, in this order:

1. **The four tools** — "Start with the numbers that matter to you": Mortgage calculator · What can I afford? ·
   My home value · Ask Myli (`GeoToolsRow`). Tools first, above the article.
2. **"Real estate in {Place}"** — the census-fed welcome article (or the curated / weekly fallback), then a
   **Sources** line naming the Census Bureau (when a census figure was used), Heartland MLS with its as-of
   date, and HouseLoop. When no welcome article has reached a place, the ACS row becomes the first paragraph.
3. **"Housing market trends in {Place}"** — ONE section: four tiles (Homes for sale · Median list price ·
   Median days to offer · Months of supply) and the trend table underneath, read from `hl_market_stat`
   by `lib/geo/market-trend.ts` (latest complete period · the period before · a year ago · change). The
   column heads name the period ("Aug 2026"), never "This month" — the current month is partial. Zips carry
   trailing three-month windows because that is the only period the table holds for them.
4. **"Real estate FAQs about {Place}"** — the sixteen live-number questions, expanded, one `FAQPage` block.
5. **The tail** — thirteen shelves in four groups, ONE shelf component (`GeoTail` → `TailShelf` → `ShelfTable`),
   built as data by `lib/geo/geo-tail.ts`.

All four upper headings and every shelf heading are the two-tone `SectionHeading` at its 19/26 size.
`GeoSeoContent` renders 1–4; `GeoTail` renders 5. Sections render in this order and nothing re-sorts them.

## The tail — thirteen shelves, one component

| group | shelf id | heading | rows | the pill |
|---|---|---|---|---|
| ① the place itself | `schools` | Schools serving {Place} | districts · high · middle · elementary, counted from `Listing`'s school columns under the facet bank's predicate, with median list price | toggles |
| | `newly-listed` | Newly listed in {Place}, ST | listed inside the just-listed window (the registry's `maxDom`) | links to `/…/just-listed` when that page clears the gate; N is that page's count |
| | `under-contract` | Recently went under contract in {Place}, ST | most recent pendings | links to `/…/under-contract` (new registry row) when it clears the gate |
| | `popular` | Popular home searches in {Place} | market-state facets (just listed · price reduced · open houses · coming soon · new construction · luxury · 55+ · under contract) with the count each facet page renders | — |
| | `price` | Homes by price in {Place} | the price-band facets (nine new registry rows plus the three that existed), one axis only | — |
| | `feature` | Homes by feature in {Place} | every counted value of the facet bank plus the registry's attribute facets, most common first; linked only when its page clears the gate, plain grey otherwise | toggles |
| | `proptype` | Search by property type in {Place} | the per-type market profile (city and county only) | toggles |
| ② its neighborhoods | `neighborhoods` | Nearby neighborhoods to {Place} | the nightly neighborhood cache | toggles |
| ③ nearby cities | `cities` | Search homes nearby {Place} (county: Search homes in {County}) | the county's cities, market columns | toggles |
| ④ wider | `zips` | Nearby ZIP codes | the city's (or county's) zips | toggles |
| | `every-city` | Search homes for sale in every city we cover | every city, deduped, every anchor in the HTML (`crawlAll`) | toggles |
| | `markets` | Search for homes in popular markets | the KC districts with a count | toggles |
| | `wider` | Or go wider still — county, metro and state | the eight counties and the metro | — |

The rules every shelf obeys, from the lock:

- **12 visible.** The cap is a real slice (the crawl-budget argument in `MarketTableShelf`'s docblock still
  stands); only the hub shelves flagged `crawlAll` ship their overflow rows with `hidden`.
- **Show all N ▾ on the bottom edge.** A linked pill's N is the count on the page it opens — the cage
  fetches that page and compares (`SHOW_ALL_PARITY`). A toggle pill's N is the row count, never a constant.
- **Only the first cell is a link.** The old market table linked every count cell to a `?status=` search —
  735 parameter URLs on one page. Gone by construction.
- **Zero coloured pills.** Market type is plain text in its cell.
- **On the phone, a table never scrolls sideways.** Every column but the first and the one flagged `phone`
  collapses below `lg`; one DOM for both widths, so the crawler reads the same anchors in either frame.

## What was retired on 2026-09-09

Retired by the call site no longer rendering them (the files stay on disk): the data bank ("{Place} by the
numbers" and its pill chips), the overview prose, the listing-overview tiles, the public-data tiles,
`WeeklyMovers`, `GeoDirectory`'s two market tables, the schools strip above the FAQ, the nine-tile stat grid,
and `HomeSeoTail`'s five shelves on the home page (the home page and `/kansas-city` now render the same
`GeoTail`, metro-scoped). Their facts moved, not vanished: the bank's counted values are the feature shelf,
the census row is the article's first paragraph, the movers are the newly-listed and under-contract shelves.

## The cage

`node tools/seo/page-structure-cage.mjs --cage` renders every geo type (county · city · zip · neighborhood ·
metro · property-type · facet · the home page) and refuses, by name: `GEO_LOCK_ORDER` (tools → article →
trends → FAQs), `DATA_BANK_RETIRED`, `ONE_SCHOOLS_SECTION`, `EVERY_LIST_IS_A_SHELF` (an `<h2>` below the FAQs
that no shelf owns), `TAIL_SHELVES` (present, in the builder's own `TAIL_SHELF_ORDER`), `SHELF_CAP`,
`SHOW_ALL_PILL`, `SHOW_ALL_PARITY`, `ZERO_PILLS`. Red-proven against production on 2026-09-09 before the fix
landed: 42 geo-lock refusals across the geo types, each one of Zach's findings by name. `--selftest` plants
the desk's pre-lock measurement and each single defect with its control.

## What the SEO Revamp shipped on 2026-09-08 (Phases 0, 2 and 3)

**Phase 0 — the entity.** Every page renders exactly one `Organization` JSON-LD node for HouseLoop (name, url,
logo, telephone, email, areaServed) with `sameAs` pointing at the Zillow and Google Business profiles and nothing
else; the blog and listing pages reference it by `@id` instead of inlining stubs. The cage arm `ORG_JSONLD`
refuses a page without it. The brand-term baseline was recorded on the day (0 impressions for "houseloop" or
"spradling" against 14,477 total).

**Phase 2 — the words.** The welcome-article slot prefers a real article over the weekly market blurb (the
precedence bug at the top of `GeoSeoContent`). The article comes from the Inngest function
`geo-welcome-article-generate` (Haiku, fed the census rows in `hl_geo_public_stat` + MLS figures, the ACS period
cited in prose) and is stored under `welcomeArticle` in `hl_geo_page.payload`; the weekly per-tier page jobs now
preserve that key on their rewrite. The four-tools row renders all four tools on city, county and zip pages.

**Phase 3 — the long tail.** Five cage arms landed first (`GATE_HOLDS`, `FACET_IS_A_SLUG`, `FACET_LINK_FILTERS`,
`NO_ORPHAN`, `PARAM_URL_BUDGET`). A facet is a real slug page (`/kansas/johnson-county/overland-park/wood-floors`),
filtered by the JSONB containment predicate on the feature module, gated at 20 homes for city and county (a thin
facet renders `noindex` with a canonical to its place page and mints no anchor), listed in the sitemap chunk that
carries geo pages, and reachable from the module's chips in the facet bank. `FOOTER_EVERY_PAGE` refuses a page
without the one site footer (the blog was missing it).

## The individual listing page — the lower order, to its lock (shipped 2026-09-09)

The listing page is the one genuine second shape of the site, and its lower half is built from the pinned lock
`docs/wireframes/listing-page-LOCKED-2026-09-09.html` (steps 3 and 4 of the SEO Revamp board, verbatim). Zach
walked production at 05:50 on 2026-09-09 and found three drifts from that drawing; all three are closed.

**The order, both faces.** … price history → tax → payment estimate → schools → **"Similar listings and the
{City} market"** → **"Look throughout {City}, {State}"** directly under it, inside the same box → **"Frequently
asked questions about {address}"** → the geo tail (popular searches → nearby cities → zips → counties) → the site
footer. The phone sheet renders the same order (rulings #257.319d/e); the earlier desktop order from the 9/08
Part 2 frame (Similar → FAQ → Look throughout) is superseded by the lock.

**Similar listings** (`components/listing/SimilarListings.tsx`) is now the one section: a two-tone heading
(`SectionHeading`, kicker "Similar listings" over the phrase "and the {City} market") above the bordered shelf box
(`SeoShelfBox`, the same `rounded-[14px] border-[1.5px] border-hl-brand` box the home and geo tails wear). Inside
the box: the three `ListingCard`s as a plain sideways carousel (one full-width card per swipe on the phone, three
across on desktop) — no "See all in this area" tile and no chevrons, because the lock draws neither and Zach's
words were "there is no see more, it's all in-page scroll" — then a hairline and the "Look throughout" block.

**Look throughout** (`components/listing/CityParagraph.tsx`) renders the lock's two paragraphs of real comparison,
every place a link: the city's for-sale count, under-contract count, median sale price and median days to offer,
then "This home is priced $X below/above that median"; then the county (its zip count and for-sale count) and the
biggest-inventory sibling city above and below this city's median. Every number is the nightly
`hl_geo_market_stats` row the city page itself renders, so the count here equals the count its link lands on.
ez's compare-and-search sentence and save-a-search nudge are gone as filler, per the lock's own note.

**FAQ** (`components/listing/ListingFaq.tsx`) wears the same two-tone heading and, on desktop, the same box; the
lock's phone frame draws the rows bare, so the box is `md:` only.

**"Already own a home?"** (the right rail on desktop, the sheet on the phone) was a navy-filled card; navy is the
page-top strip and nothing else. It is now the two-tone heading (kicker "Already own a home?" over "What's your
home worth right now?") above the shelf box, dark text, the /sell address field with its brand-blue Go button. The
component is still `SellerAddressInput` — the one Seller Report door.
