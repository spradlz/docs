## What this page is

**Settings → Pipeline & Workflow → Lead Sources** shows every marketing source that feeds you leads, as a
**1:1 mimic of the Trigger Events page**: ONE `MenuTable`, **tabs = integrations** — **HouseLoop · Follow Up
Boss** (Company Inbox retired 2026-07-31, see below), an **Integration Defaults** band under the tabs, and
**one compact table where each source is a ROW** — `icon + name · type · status · leads · last lead · Routing ·
Manage Rule`. (The old per-source clamshell cards + KPI skyscrapers were retired; per-source performance now
lives on the source detail page, and the Lead Creation bands live on Trigger Events.)

`components/settings/lead-sources/LeadSourcesBuilder.tsx` renders it; `app/(crm)/settings/lead-sources/page.tsx`
feeds it the sources, the integration seats, and each source's resolved defaults.

## The model — Integration + Source (two independent fields)

<Warning>
**`platform` IS A DEAD WORD — retired 2026-07-31 (Zach, ruled by Lee).** This page used to call the
integration "`platform`". It doesn't any more. The surviving word is **integration**, everywhere, and it is a
**closed set of exactly two**.

`hl_leads.platform` still exists as a **legacy duplicate** (`NOT NULL DEFAULT 'houseloop'`, mig 0374). It gets
**no new readers and no new writers** — read `integration` instead. Dropping the column is cutover surgery
under Rule #0 typed approval, never casually: it is NOT NULL with a default, so a careless drop breaks writes.
</Warning>

| Field | What it answers | Legal values |
|---|---|---|
| **Integration** | **WHO DELIVERED IT** — which pipe the lead/activity arrived through. | **`houseloop` · `follow_up_boss`** — exactly two, CHECK-enforced on the run log (migs 0525/0526). |
| **Lead Source** | **WHO WROTE IT** — the marketing brand that produced the lead. | A flat brand list: `zillow` · `google_ppc` · `houseloop_organic` · `sign_call` · `phone_call` · … |
| **Site** *(derived, never stored)* | **WHERE THE BROWSING HAPPENED.** | `follow_up_boss ⇒ Zillow` (Zillow is the only website behind that pipe) · `houseloop ⇒ HouseLoop`. |

**The two fields are INDEPENDENT — a source has no lane.** `google_ppc` is legitimately valid under *both*
pipes: a Google-PPC lead that landed in Follow Up Boss reads `follow_up_boss + google_ppc`; the same campaign
run against our own site reads `houseloop + google_ppc`. Reading either field off the other is the bug this
model exists to prevent.

<Note>
**Why SITE derives from the integration and not from `hl_pixel_event`:** the pixel table is being retired
(it is the **raw tier** — write-only, and a reader querying it for lead behaviour is a bug). A rule that says
"pixel rows are HouseLoop" dies with the table. The integration outlives it.
</Note>

**Manual is an entry *method*, not a source**, and **relationships** (Past Client is what a lead *becomes*) are
not sources — neither appears here.

## ⚠️ `hl_lead_sources.platform` is DEPRECATED — do not backfill it

## Lead-source canonicalization — the six FUB buckets

*(Moved here from the Follow Up Boss guide 2026-07-31 — the source model has ONE home. This is the
FUB-specific half: how FUB's messy strings fold into the canonical buckets, and why we tag rather than rewrite.)*

Follow Up Boss carries **hundreds of messy source strings** ("Zillow Preferred", "Premier Agent", "Trulia.com",
"Agent COI", "&lt;unspecified&gt;", "FiveStreet", "Opcity"…). Importing those verbatim would give HouseLoop an
un-filterable soup. So every FUB lead's source is **folded into exactly SIX canonical buckets** — the normalized
list you import into and report on. Locked by Zach 2026-07-04: *"clean lead sources — six buckets, everything
else is noise."*

| Canonical bucket | `hl_lead_sources` key | What folds in |
|---|---|---|
| **Zillow** | `fub_zillow` | Zillow, Zillow Preferred, Premier Agent, Zillow Flex, **Trulia** (Zillow-owned) |
| **Google PPC** | `fub_google_ppc` | anything carrying the `Google Adwords PPC` tag (tag wins, even over a Zillow source string) |
| **Google Organic** | `fub_google_organic` | `google` / `google organic` source text |
| **Realtor.com** | `fub_realtor` | `realtor.com` |
| **PC SOI** | `fub_pc_soi` | Agent COI, SOI, **Referral** (a referral is relationship-based), SRG past client |
| **Other** | `fub_other` | everything else — FiveStreet, Opcity, Homes.com, HomeLight, unknown/new strings |

**The fold happens in ONE place** — `lib/fub-import/source-canonicalize.ts` (`canonicalizeFubSource`), the single
map. Three rules, in order: ① the **`Google Adwords PPC` tag wins** → Google PPC (it beats the source field);
② the **fold map** matches the source text → its bucket; ③ **default = Other** — an unknown or brand-new string
NEVER invents a bucket, it lands in Other. Nothing is lost: the fine original origin is preserved on the lead as
a **`Lead Source - <original>` tag** (e.g. `Lead Source - Opcity`). The buckets are seeded by **migration 0315**;
the old hardcoded `Zillow.com` import label was killed so imports stamp the *real* resolved bucket.

### We do NOT rewrite FUB's Source field — we tag (it's immutable)

**Follow Up Boss's `source` field cannot be changed via the API** (probed 2026-07-04 → "No valid fields").
So inside FUB, a lead's Source stays exactly what it always was — "Zillow Preferred", "Premier Agent",
"zillow.com" — **forever**. We never touch it. The normalized bucket lives in FUB as a **tag** instead.

The one-time backfill — a registered Inngest function (`fub-source-sweep`, event `fub/source-sweep.run`,
**manual, no cron**; Rule #0-gated, reversal file saved first) — stamped the entire book:
- **`HL Source: <bucket>`** — the canonical bucket (e.g. `HL Source: Zillow`), for filtering inside FUB.
- **`Lead Source - <origin>`** — the exact original string preserved (e.g. `Lead Source - Zillow Preferred`).

Tag writes are GET → merge → PUT off the **live** FUB record (never the mirror), so a stale array can't delete a
tag a lead just earned. **Verified live (mirror, this session):** **48,920 of 49,234** people carry an
`HL Source:` tag (**28,072 = Zillow**); only **64** Zillow-family stragglers still need it.

<Warning>
**The `HL Source:` tag is the normalized signal in FUB — the Source field is NOT.** Inside FUB, "Zillow
Preferred" (and the other raw strings) will always show as the Source; that's expected and unavoidable (FUB owns
that field). The `HL Source: Zillow` tag is where the bucket lives. Likewise, **do not read
`fub.people.source` in our mirror as the canonical bucket** — the mirror re-syncs FUB's raw source over any fold,
so it also shows the raw strings. The canonical bucket is derived by the resolver / carried by the tag, never
stored durably in a source column.
</Warning>

### How HouseLoop gets the bucket (it derives, not reads the tag)

When a FUB lead **imports into HouseLoop**, the import runs the raw Source string through the fold map
(`canonicalizeFubSource`) → resolves the bucket → stores it on the HouseLoop lead (`hl_leads.source_id`) and
adds the `Lead Source - <origin>` tag. So the HouseLoop lead's Source = **Zillow**, even though FUB's field says
"Zillow Preferred". HouseLoop derives the bucket from the raw string — it does **not** depend on the
`HL Source:` tag (the only tag it reads as an override is `Google Adwords PPC` → Google PPC).

**Where you see it:** the **Lead Sources** page (this page) — the six-bucket rows under the Follow Up Boss tab (click a bucket
to filter its leads); each imported lead shows its bucket as its Source, plus the `Lead Source - <origin>` chip
on lead detail. New inbound is canonicalized the same way at import time. Live bucket spread across 49,234
`fub.people` (by `HL Source:` tag): **Zillow ≈ 28,072**, the rest split across Google PPC · PC SOI · Realtor.com ·
Google Organic · Other.

## Integration Defaults — the per-tab band

Under the tabs, the **Integration Defaults** band reads the tab's `__platform_<int>__` seat row and shows the
four defaults every source in that tab inherits: **Assigned to · AI · Workflow · Set stage**. **Manage Defaults**
opens the routing editor on the seat itself (the seat is the root — no inherit/custom toggle there, its fields
*are* the defaults).

The seats: `__platform_houseloop__`, `__platform_fub__` (`source_type='platform'`, `is_selectable=false`, so they
never show as pickable sources). ⚠ The seat KEYS still carry the retired word `platform` in their literals — they
are identifiers, not vocabulary, and renaming them is cutover work. `__platform_inbox__` is retired with the lane. Follow Up Boss's seat is set to **owner = Ana +
her AI clone on, no standalone AI** — so every FUB lead lands on Ana and her clone covers it.

## Routing — inherit vs custom, and the non-destructive toggle

Every source either **follows its integration defaults** or has **its own custom rule**. The **Routing** column
is a live control that shows and flips this:

- **`use integration defaults` toggle (per row).** ON → the source uses its integration's defaults ("Using
  integration defaults"). OFF → its own custom rule (blue `↑ Ana Spradling · Attempted Contact`) or, if it never
  had one, "Inherits integration defaults" (gray).
- **Per-tab MASTER toggle** in the Integration Defaults band — *"Use these defaults for all N {integration}
  sources"* — flips **every source in the tab** at once. It reads ON only when all sources in the tab are on the
  default.
- **NON-DESTRUCTIVE.** Turning "use integration defaults" ON does **not** delete a source's custom rule — it
  *suspends* it. The row reads "Using integration defaults · **custom rule saved**", and turning it back OFF
  **restores the exact last-saved rule.**

**How it's non-destructive (the mechanic):** `hl_lead_sources.use_integration_defaults` (bool, mig **0408**) is a
suspend flag, separate from the source's `default_*` values. `resolveSourceDefaults()`
(`lib/lead-sources/resolve-defaults.ts`) reads it via a CTE that NULLs the source's own overrides **only when the
flag is on**, so the `COALESCE(source, seat)` falls through to the seat — the stored values are untouched and
resolve again the moment the flag is cleared.

## Manage Rule — a source's own routing rule

**Manage Rule** (`ManageRoutingRulesModal.tsx`) edits one source's rule. It opens with an **inherit vs custom**
segmented toggle:

- **Use integration defaults** — the fields are greyed + read-only, pre-filled with the **real inherited values**
  (never blank), so you see exactly what the source follows. Save sets `use_integration_defaults = true`
  (non-destructive).
- **Custom rule for this source** — the fields turn on, pre-filled from the inherited values as a starting point;
  Save un-suspends the source and writes the explicit override. A **↺ Reset to defaults** link flips back.

The fields:

- **Default human owner** — a HUMAN (shown by name, e.g. *Ana Spradling*). Drives the clone below.
- **Owner's AI clone** — a toggle: *"Let {owner}'s AI clone respond to these leads."* The clone is a **mode on
  the human** (mig **0392**), never a separate entity — it replies **as** the owner (their name + line). Writes
  `clone_default_on`; at intake the lead goes into clone mode (`ai_mode_enabled`) and the runtime resolves the
  owner's clone. See [Myli & AI clones](/guides/myli-system).
- **Standalone AI responder** — OPTIONAL (None allowed, no forced Myli): a generic AI (Myli) in the lead's right
  column. Clones are never listed here.
- **Appointment hand-off · Default stage · Default tags.**

Per-event workflow/notification routing is NOT here — it's set per trigger event on
[Trigger Events](/guides/trigger-events). Manage Rule is the source-level default rule only.

## The resolver — one hierarchy for every lead-creation path

`resolveSourceDefaults(sourceId)` (`lib/lead-sources/resolve-defaults.ts`) is the ONE resolver every creation
path uses (FUB import, website intake, manual add, runtime sender rule). It resolves **source override → the
integration seat** via the real FK `hl_lead_sources.integration_id` (mig 0373) — never CASE-matched text —
and **suspends the source layer when `use_integration_defaults` is on** (above).

**FUB pull-in applies the resolved owner (fix, 2026-07-14):** `lib/fub-import/import-fub-lead.ts` now sets a new
lead's owner from the resolved `default_assigned_user_id` (source override → `__platform_fub__` seat = Ana), so a
FUB pull lands on Ana instead of minting unowned and being grabbed by the Myli ownerless-fallback.

## The structural guarantees (locked 2026-07-11)

Full law: `GT/GT - ACTIVE/GT_HOUSELOOP_INTEGRATION_SOURCE_MODEL_PRD.md` — "the integration is a relation, not a
word."

- **A source's integration is a real FK** (`integration_id` → the seat row, mig 0373) — never text matched by
  CASE. The seat-key literals live in exactly one file (`lib/lead-sources/integrations.ts`).
- **Every lead has an integration at birth** — `hl_leads.platform` is `NOT NULL DEFAULT 'houseloop'` (mig 0374);
  every creation path stamps `platform` + `channel` from the source row.
- **`is_selectable` separates sources from config seats** (mig 0372) — the seat rows live in the same table but
  never appear here or get deleted.
