> **This is the AGENT'S mobile app** — Zach's HouseLoop in his pocket. It is not the client
> dashboard (that lives under [Client dashboard / Myli MVP](/master-plan/client-dashboard)).

## What it is

A separate mobile shell inside the CRM app: **`crm.houseloop.ai/m`**. Built 2026-06-21 (Zach
directive), screens locked as HTML wireframes 7/25–7/26 and ported node-by-node under the
**wireframe-is-the-truth** law (`UI_ITERATION_HTML_FIRST`). It shares the CRM's database, APIs,
and login — the middleware gates `/m` and redirects to `/login` when unauthenticated. The whole
tree (`apps/houseloop-crm/app/m/**`) is additive: it has its own layout (no desktop
Sidebar/Topbar) and can not affect the desktop CRM.

## The screens (all shipped)

| Route | Screen | What it is |
|---|---|---|
| `/m` | **→ Inbox** | Opening the app lands on everything that needs an answer (Zach locked 7/26) — texts, calls, tour requests and new leads in one list. (It landed on Messages before that, and the Activity firehose before that.) |
| `/m/inbox` | **Inbox** | One row per person, newest first, showing only what needs a response. Screen 1 of the locked inbox wireframe. |
| `/m/inbox/[leadId]` | **Thread** | One person, every channel, one screen — texts, calls, emails, Zillow in-app messages and requests interleaved in time. Screen 2 of the locked inbox wireframe. |
| `/m/comms` | **Comms** | The conversation firehose: texts · calls · emails (person-to-person), newest first, live via SSE. Tap any row → the lead. |
| `/m/leads` | **Leads** | The simple list (Zach 7/25: "our leads page is much more complex than it needs to be"). Screen 4 of the comms wireframe. |
| `/m/leads/[id]` | **Lead** | Summary · All · Website tabs. Screens 5–7 of the comms wireframe. |
| `/m/leads/new` | **New lead** | Minimal add-a-person. |
| `/m/calls` | **Calls** | "Recents" — deliberately the iPhone Phone app. Tapping a number calls through the Twilio line they called. Screen 3 of the comms wireframe. |
| `/m/activity` | **Activity** | The real-time run-log of everything, with filter chips (All · AI · Texts · Calls · Emails · Notes · Stages · Website). Event-driven via the run-log SSE stream — zero polling. |
| `/m/trash` | **Recently Trashed** | The recycle bin — everything a swipe threw away lands here and stays restorable (Zach 7/25: "let's just say 'Trash' and 'Recently Trashed'"). |

## The design record

Two LOCKED wireframes are the build spec — the React screens are node-by-node ports of these
drawings, and any change to these surfaces goes **into the wireframe first**:

- [`docs/wireframes/mobile-comms-LOCKED-2026-07-25.html`](/guides/mobile-screens) — Calls, Leads, Lead detail (screens 3–7)
- [`docs/wireframes/mobile-inbox-LOCKED-2026-07-26.html`](/guides/mobile-inbox) — Inbox + Thread (screens 1–2)

## Where it's headed

The signed [seat model](/schema-lock/target-model) makes the next evolution natural: team
members as first-class profiles, one thread per person across every lead, and group messages
filed on every record they touch. That future spec is being drafted — this page documents only
what is live.
