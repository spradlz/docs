## 🧹 THE DATA HYGIENE LAW (Zach, 7/31 PM — constitutional, delegated to Lee end-to-end)

**"There cannot be a way to get to the same answer through two separate columns. There should not be
lazy columns — last_communication should be a QUERY from the run log, not a hardcoded stamp; that's how
shit drifts. Minimum number of tables, minimum number of columns. If it's unused or empty now, delete
it — we'll name it for when the piece gets built the right way. Every time I had an idea, you guys spun
up a table or added columns without checking if we already had something. Zero data hygiene has taken
place in this CRM — I own that — but we are enforcing it now."**

The four rules, enforced:
1. **ONE PATH PER ANSWER.** Two columns/routes to the same fact = one dies. No exceptions.
2. **DERIVE, DON'T STAMP.** A fact computable from the run log / another table is a QUERY (or a
   DECLARED regenerable cache) — never a hand-maintained stamp that can disagree with the source.
3. **NO SPECULATIVE SCHEMA.** A column/table for an idea that isn't built yet does not exist — it gets
   NAMED in the plan and BUILT when its feature is. Unused/empty now → dies now (with judgment: a live
   engine's columns survive even if quiet).
4. **THE CAGE:** every new column migration must name its READER in a `-- READER:` line, or the lint
   rejects it. Ideas stop minting schema.
5. **THE CACHED-POINTER RULE (Caleb's Redfin autopsy 7/31 PM, AMENDED by Zach's correction):** every
   cached external pointer names its RE-VALIDATION check AND its DISCARD threshold — validate on use,
   discard only on unambiguous contradiction. The guard is ASYMMETRIC because that's where the risk
   lives: **SEARCH is strict** (bad pointers are born there — all 36 wrong-house urls came from
   first-ever searches, the fast path never misfired once) · **LANDED pages are verified** (walk away
   rather than write a neighbor town's value) · **SAVED pointers are PROTECTED** (Zach: Redfin/Zillow
   never reindex a home url — "that's their SEO moat" — so a correct saved url is correct FOREVER, an
   ASSET; discard only on wrong-STATE, because our own address row is the less reliable side of a
   same-state disagreement).
6. **THE EXTERNAL-ID LAW (Zach, 7/31 late — "it should have been just dotloop_id, not hardcoded
   srg dotloop id"):** an external system's id column is **`<system>_id`** — `dotloop_id`, `fub_person_id`
   stays only because *person* disambiguates FUB's several id spaces — THE TABLE SUPPLIES THE NOUN.
   The four existing `dotloop_<thing>_id` columns are tagged **legacy spelling, do not cite as
   precedent**; they ride a future rename batch (live data + estate ownership gate the timing).
7. **THE AUTHORITY (Zach, 7/31 PM): LEE OWNS ALL DATA-SCHEMA HYGIENE.** Every new COLUMN, every new
   TABLE, every new ACTIVITY KIND goes through Lee — one authority, no exceptions, agents included.
   The kind gate already enforces this for kinds; the migration lint gains the same gate for columns
   and tables (a schema-creating migration without Lee's approval line does not push).

Execution: Lee runs the full column diet end-to-end from PRODUCT-CODE derivation (receipts per verdict),

## ⚖️ THE ACTOR-AGNOSTIC VOCABULARY LAW (Zach, 7/31 PM — constitutional)

**"The whole CRM is designed so that if a human can do it, the AI can do it — so an ai_ prefix on an
action is REDUNDANT."** One vocabulary of ACTIONS; the WHO (human · AI · clone, name, role) is carried
ENTIRELY by the user on the row — never by the kind. There is no `lender_looked_up`, no
`tc_looked_up_document`, no `ai_<anything a human could also do>` — a lookup is `property_searched`
whether Ana did it or Myli did; a text is `sms_sent` whether Zach typed it or his clone did.
**THE TWO-SIDED TEST (Zach's full statement, ratifying Adam's carve-out, 7/31 PM): "If anyone can do
it, there's NO prefix. But if it's genuinely a thing only the AI can do, it NEEDS the ai_ prefix."**
Both directions are requirements, not permissions: an action a human could take never forks by actor
(no prefix, the user carries the WHO) — AND an AI-machinery event with no human equivalent (the memory
engine's own operations: `ai_context_built`, `ai_fact_captured`, `ai_send_blocked`) MUST wear the
prefix, because there the prefix names the ACTION's nature, not the actor. Receipts from today: `ai_search` deleted (was `property_searched` + an AI user) ·
`ai_clone_stepped_in` deleted (was the real channel kind + an AI user) · `property_looked_up` folded
(was `property_searched` + Myli's id). New kind proposals are tested against this law FIRST.
