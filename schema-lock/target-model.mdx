## The pour — how we get there without the software ever stopping

1. **A · BEAMS (additive)** — WEB gets a migration ledger + DDL trigger (today ~18 WEB tables exist only as
   `CREATE TABLE IF NOT EXISTS` in request code — unenumerable) · `document_signatures` + sealed/original PDF
   columns + sha256 · `hl_lead_custom_value` · `hl_lead_activity.website_hlid` · message thread ids /
   attachments / draft status · run-log cost columns · the loop↔transaction link.
2. **B · REPOINTS (one fold per push, alias-closure pattern)** — email → `hl_messages` · phone assignments →
   `hl_phone_numbers` · tokens → `hl_oauth_connections` · settings documents → `hl_settings` · segments merge ·
   the stage_id dual-write dies with its four writers in one commit.
3. **C · CUTOVER SURGERY (Zach in the room, ONE-COMMIT-RENAME)** — the person merge · trigger-events →
   catalog succession + the kind FK move · the `hl_transactions` split into `loops` + `transactions` ·
   FK-ghost drops (hl_agents, hl_channels, hl_conversations) · **the actor→user vocabulary rename**
   (Zach 7/31: "we don't have actor anymore, it's user and user_type") — lands as `user_name` /
   `user_type` / `user_id` (bare `user` is a Postgres reserved word), 58 files, ONE commit; until then
   the `hl_lead_conversations` view is the adapter — its OUTPUT already speaks the new names, so readers
   never migrate twice.
4. **D · RETIREMENT BATCHES (Rule-0, ongoing)** — every fold frees tables; every batch snapshots first;
   the schema lock ratchets at each new floor (233 → 167 → 160 → …).
