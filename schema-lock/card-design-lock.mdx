## What this is

On 2026-07-30 Zach locked the universal design for **every card in the lead-detail feed** — messages, notes,
emails, calls, inquiries, registrations, website activity, appointments, tasks, deals, AI actions, system
moves. It was designed the constitutional way (`UI_ITERATION_HTML_FIRST`): iterated as an HTML wireframe,
signed, then ported node-by-node.

**The pinned wireframe is the truth:** `Docs/wireframes/card-chrome-locked-2026-07-30.html` (in the repo,
version-pinned). If this page and the wireframe ever disagree, the wireframe wins — fix this page.

## THE GRAMMAR — one sentence

Every card is: **[family icon in a colored circle] + a plain sentence "[Who] [did what] [· the facts]"**
(+ a VIA chip when it came from a portal) · **date+time top-right, always** · **hover actions below the
date, star first**.

**THE SENTENCE LAW (Zach ruled "run it" 2026-07-30, migration 0513):** the verb phrase is a **column on
the signed activity catalog** (`hl_activity_catalog.sentence`) — "created a note", "changed the stage",
"requested a tour" — authored for all kinds in one reviewed seed. The renderer is one dumb line:
`who + the catalog's sentence + the payload facts`. A NULL sentence renders the label atomically
(insight/system kinds, and the email fallback — the real EmailCard resolves the true sender).
- **Full names, always**: "Msale Olongo requested a tour", "Zach Spradling created a note". The WHO comes
  from the actor lane (lead / agent / Myli / System), never guessed from message direction.
- **Kind pills are DEAD** — no "Note Added", no "Stage Changed", no "Phone Call Logged". The icon carries
  the kind; VIA (source) is the only chip a card may wear.
- **Payload facts ride the sentence**: "changed the stage · 1st Appt Set → 1st Appt Met" · "Outbound call
  to Msale Olongo · from your line · 1:52" · Myli's facts: "Myli captured a new fact — Search Criteria"
  with the slot underneath and the evidence quoted below (never the raw payload salad).
- **Email senders keep their names** (migration 0512): the Gmail sync captures the From display name;
  the thread API resolves name → known `hl_users` identity → bare address; the card reads FUB-style
  (JN avatar · **John Nelson** › recipients · date underneath).

## The five laws

### 1. The chrome zone (top-right, every card)

- **Row 1 — always visible:** date + time, ONE format everywhere (`Jul 14, 12:32 PM`), same pixel position
  on every card type. Never vertically centered, never floating.
- **Row 2 — appears on hover, BELOW the date, never overlapping:** the action icons.
  **☆ is ALWAYS FIRST (far left of the row), on every card.** Per-family extras follow it
  (note: ✏ edit · 🗑 delete; message: ↩ reply).
- **Email is the one exception with an addition:** it keeps a **persistent ⋯ kebab pinned far right at all
  times**; its other buttons and the hover-☆ sit to the kebab's left. The date stays in the standard corner.

### 2. NO user color pills — ever

The actor is **plain bold text in the sentence** ("**Zach Spradling** added a note"), SureSend-style.
Per-user colors are whack-a-mole for every future user type — banned. When the headline already speaks the
name ("Renita sent an in-app message"), the name is not repeated. The old three-pill soup
(`[Zach Spradling] [Note] [Note Added]`) is dead.

### 3. PINK = AI, reserved

**`--hl-ai-pink` #EC4899 (the AI-summary pink) belongs to Myli/AI alone.** Anything an AI does wears the
pink ✦ Sparkles. No other family may use pink **or purple** — purple retired from the feed entirely
(email was purple; it is now **teal #0F766E**). System/atomic moves (stage change) wear the mechanical
**Settings** icon in slate — machinery, never purple.

### 4. The catalog paints the card — never a hardcoded map

Icon + color per kind live as **columns on `hl_activity_catalog`** and flow into the UI through
`activity-badges.generated.ts` (regenerated by `scripts/generate-activity-badges.mjs`; parity gate in the
caged pre-push). The compact-row icon tile in `CenterLane.tsx` is painted by the catalog accent + icon —
its old hardcoded kind map survives only as a fallback for uncataloged kinds.
**To change a family's color or icon: one catalog `UPDATE` + regenerate. No component edits.**

### 5. The locked pieces that must not be touched

- **Home-card links:** Zillow-origin event → `Look up on HouseLoop · View on Zillow`.
  HouseLoop-origin event → `View on HouseLoop` only. Locked in prod before this design; unchanged by it.
- **In-app Zillow messages always carry the little round Zillow circle** — even on a house hero.
- **Registrations are ALWAYS hero cards** with a big round SOURCE icon: HouseLoop mark, Zillow mark, or a
  generated color+initial circle for unbranded sources (gmail-avatar style).
- **Hero shapes for inquiries/tour requests** (icon chip on the photo, quote box, VIA pill) — locked.

## How to add or change a card (the maintenance rule)

1. **New kind?** Catalog row first (key, label, `event_activity` phrase, icon, color, `card_layout`).
   The feed inherits everything — no component edit for paint or label.
2. **Recolor / re-icon a family?** One catalog `UPDATE` migration + `node scripts/generate-activity-badges.mjs`,
   committed together (the parity gate enforces it).
3. **New card SHAPE (a sixth body, a new action set)?** STOP — that's a wireframe change. Edit the pinned
   HTML, get Zach's re-lock, then port. A shape that exists only in React is vibe code.

## Why this exists

By 2026-07-30 the feed had drifted into pill soup: a note rendered THREE pills (orange actor + kind + label)
plus a gray icon; stars floated over dates; dates sat in different corners per card type; requests wore
purple (AI's color); email wore purple too; and every new user type would have demanded its own pill color.
Zach called it on a screen-walk, designed the fix as a locked wireframe, and this page is that lock made
permanent — so no future agent "improves" a card back into drift.
