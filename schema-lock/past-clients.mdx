## The shape in one breath

**One truth spine, everything else is evidence or a pointer.** `hl_srg_canonical` (one row per DEAL: client × house × side, keyed `pc_id:hlid:our_side` — never MLS in the key) is THE deal record. `hl_srg_past_clients` (one row per PERSON) carries who they are and their bucket. `hl_srg_past_client_homes` (one row per person × home) carries the relationship to each rooftop. Every value number lives on the **WEB `Listing`** — the CRM points by `website_hlid` and **never copies** (no copy = no drift).


## ZACH'S SEVEN RULES — signed 2026-07-30 (eyeball catches that became law the same day)

1. **THE SOURCE HIERARCHY LAW.** Canon = `hl_srg_mls_deals` + `hl_mls_property_history` (the MLS-UI harvests). Rank-2 = real `Listing` rows, dates cross-checked against canon. **`Listing.priceHistory` (Zillow, address-glued) is BANNED from the book pipeline** — it carried the neighbor's history and falsely flagged the Frittz. A weak source raises a QUESTION; only canon writes an ANSWER.
2. **THE SELF-CONSISTENCY TEST.** A price history that does not contain the house's OWN sale is not that house's history (61 contaminated carriers found).
3. **THE CONDO UNIT GUARD.** A harvest/building event joins a unit-keyed home ONLY when it NAMES that unit (shared parser — handles the MLS's `UNIT##2002` double-hash). An ambiguous, unit-less event NEVER counts.
4. **THE IDENTITY KEY BEATS THE COLUMN.** A home's unit reads from `identity_key`'s middle segment; the `unit` column is a cache that goes NULL. Key-vs-column drift is a red-flag sweep (Guardian Tier 5).
5. **ROSTER MATCHING NEEDS THE INITIAL.** A surname match requires a first-initial match with a roster member of that surname — no more Blaire-via-Jordan Lawrence.
6. **DISPOSITION = SISU DATES + THE MLS SHEET + THE HARVEST** (the Mettman rule): the sheet's `close_date` beats the web listing's `soldDate`; the client's own later sell deal beats everything.
7. **THE CONFIRMATION STANDARD.** Every buy disposition carries a chip — canon ✓ / listing-only / no-harvest / mismatch. Unconfirmed SAYS SO; gaps are filled by harvesting, never substituted.

## The rulings (the lock session's verdicts)

### 1. ONE disposition vocabulary — and it is NOT transaction status
The child table's four words are canonical: **`owns` · `sold_moved` · `lost_listing` · `lost_buy`** (matches the deterministic disposition engine). The canonical table's synonyms (`still_owns`/`sale_side`/`lost_opportunity`/`sold_repped_by_us`) MAP onto these — one migration, alias-documented.
**Deliberately NOT merged into the transaction ladder**: `transaction_status` (pending → closed → lost) answers *"what happened to a deal"*; disposition answers *"what is this rooftop's relationship to us now."* Two questions, two vocabularies — forcing them together would be a false merge (the interchangeability test).

### 2. The `verified` gate values — SIGNED
`PASS · WARN_NO_ADDRESS · WARN_UNIT_DROPPED · FAIL_WRONG_UNIT · FAIL_WRONG_HOUSE · FAIL_NOT_SOLD · FAIL_PRICE`
Locked as a CHECK constraint on `hl_srg_canonical.verified`. The resolver door refuses non-PASS. Signed by Zach 2026-07-30.

### 3. `identity_key` format — LOCKED
**`street::unit?::zip5`** — unit is the optional MIDDLE segment. The **columns are the source; the key derives** — when a column repair (like the 7/27 zip fix) makes key and column disagree, the KEY regenerates by migration, collisions resolve oldest-wins with the quarantine trail. Key-vs-column drift is a red-flag query in the reconciliation gate.

### 4. The three words, applied here
The canonical row IS a **transaction** · "deal" is display language · `hl_srg_loop` is the **loop** (the immutable party/document record). Existing table names that predate the law (`hl_srg_deal_ledger`) are **grandfathered in place** — registered here, renamed only if a natural migration touches them. No churn renames.

### 5. `hl_srg_master_houses` repoint — ASSIGNED
A truth view must not stand on a deprecated table (`hl_srg_pastclient_gt`). Caleb repoints it onto the canonical spine; the gt table then joins the dead list.

### 6. Value provenance — CONFIRMED COMPLIANT + one addition
All value lives on WEB `Listing`: `hlEstimate(+Low/High/Source/At)` · `zestimate(+Low/High)` · `redfinEstimate(+Low/High/Url/At)`. The signed `hlEstimateSource` provenance list gains **`zestimate_spread_rule`**: `zestimate · zhvi_floor · sold_floor · sold_price · fresh_contract · closing_price · zestimate_spread_rule`. Trend series = **`hl_value_history`** (the `Listing.valueHistory` COLUMN is a dead lookalike — never read it). Photos = `photosCached` objects, never the empty `photos` jsonb.

### 7. ⚖️ Sitting — the dead weight
The parent's `current_home_*` columns + the `closings` jsonb (221 entries with lost years — display-only, never a ledger input) and section D's dead tables (`hl_srg_pastclient_gt`, the staging/quarantine litter, empty `hl_transactions`) go to **Zach's Table Sitting** for Rule-0 sentences. ## Evidence tables — inputs only, with their traps

`hl_srg_mls_deals` (only `Sold` is a closing; buy-side rows name OUR client, list-side rows name the BUYER) · `sisu_transactions` (frozen; absence proves nothing; address is veto-only) · `hl_srg_loop` (party truth; agent fields are JSONB objects — read `.name`) · `hl_srg_dotloop_contracts` (a contract is NOT a closing) · `fub.*` (dossier inputs only — the no-dogfood law). **An answer is never read from an evidence table.**
