## The one-paragraph version (for humans)

HouseLoop's data lives in **two databases**: the **WEB** database (the website — homes, listings, visitors; Prisma schema, 39 models) and the **CRM** database (**161 tables**, every one listed in this section). Everything that *happens* is one of **145 signed activity kinds** (the Activity Catalog, signed by Zach 2026-07-29). Everything that *exists* is a row in a locked table. Nobody — human or AI — can add a table, column, or activity kind without the machines below letting them.

## THE CAGES — what physically stops drift

| # | Cage | What it blocks | Where it runs |
|---|------|----------------|---------------|
| 1 | **Migration numbering** | duplicate migration numbers (boot-runner loops) | pre-push, blocking |
| 1b | **Table laws** | non-`hl_` names · singular/plural twins (`hl_lead` vs `hl_leads`) · tables without a `-- GRAIN:` registration | pre-push, blocking |
| 2 | **Event-kind drift** | the generated TypeScript union disagreeing with the catalog — an invented kind **does not compile** | pre-push + compile time |
| 3 | **Catalog parity** | a kind that can be written but cannot render | pre-push, blocking |
| 4 | **SCHEMA DRIFT** | the live database differing from `schema.lock.json` in ANY way — new/changed/dropped column, index, constraint, trigger, function | pre-push, blocking |
| 5 | **WRITE-PATH TEST** *(defined 2026-07-31 · probe = the next beam, not yet a machine)* | a schema change that breaks a REAL writer while the schema still matches the lock. The blind spot it closes: on 7/31, gate 4 verified the DB matched the lock PERFECTLY while `NOT NULL` was rejecting every `logActivity` insert (explicit NULL ≠ omitted column; `void` call sites swallow the rejection — silent data loss, found by Zach in the product). The machine: after any migration touching a written table, exercise the REAL writers (`logActivity`/`logMessage`/…) in a rolled-back transaction and fail loud. Until the probe ships, the matrix in `.claude/lessons/check-constraints-permit-null.md` is the manual gate: wrong value · NULL · omitted column · **the real caller's path** | post-migration, blocking (manual until the probe ships) |
| — | **DDL attribution** | nothing — it *names* whoever touched the schema (`hl_schema_ddl_log`: who, what, when) | always-on DB event trigger |
| — | **ESLint** `hl/no-hardcoded-event-kind` | kind string literals in comparisons (the 7/28 disease) | lint |

**The migration workflow** (the only legal way to change schema): write `05XX_*.sql` → apply locally with `db/migrate.mjs` → `node tools/schema/schema-lock.mjs` → commit the migration **and** the lock in ONE push. The cage rejects anything else.

## The signed models (quick reference)

- **Activity kinds**: [the full catalog →](/schema-lock/activity-catalog) — 145 kinds, 6 sections, payload shape per kind
- **Loan ladder** (config, `hl_loan_status`): contacting → contact_made → started_application → submitted → underwriting → pre_approved → fully_underwritten → on_hold → denied† → funded† → no_longer_active†
- **The three words**: *transaction* (canonical) · *deal* (agent-facing label) · *loop* (the document container, own lifecycle)
- **The pair**: *integration* = which system carried it · *source* = the brand · transports (Twilio/Gmail) are carriers, never sources
- **The user model**: every actor is an `hl_user` (type: lead · agent · lender · ai · bot · visitor …) — "lead is a type, not a who"
