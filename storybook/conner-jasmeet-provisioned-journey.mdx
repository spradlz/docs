## ⑤ THE GAP LIST (= the living PRD for #115, the Agent Provisioning UI)

1. **No pre-approval UI anywhere** — the dashboard's "Pre-approved" ladder step stayed unchecked
   despite the staged loan state, and there is NO upload-a-letter UI (agent-side or client-side).
   The Fountain letter PNG could not be uploaded "from the UI" as Zach asked. Build: upload +
   display + the ladder step reading the real loan state.
2. **No tours/history section on the client dashboard** — the staged tour + Trish's feedback live
   on the CRM feed but the client sees nothing. Build: the toured-homes band (+ Myli's
   post-showing feedback ask).
3. **No manual "add a toured home" UI** for the agent (staged via writers tonight).
4. **The invite/welcome email is not a product feature** — composed ad-hoc tonight; build the
   template (household-aware greeting) + the "provision without sending" / "pause sends until
   dashboard deployed" send options.
5. **Magic link bypasses the phone step** — Zach described link → phone → code → 90 days; the
   magic link signs in directly with no phone capture on this path. Decide: keep (frictionless) +
   capture phone right after, or route invites through the phone-code flow.
6. **Provenance copy wrong on agent-built searches** — the chip says "Built from the homes you've
   viewed" for a search Zach built. The search writer's actor should drive the copy.
7. **Stale-session hazard (found live):** a browser holding an old session for the same email
   string passes through the magic link WITHOUT re-binding — the walk first rendered the RETIRED
   user's dashboard until cookies were cleared. Real-world twin: shared/old devices. The
   pass-through should re-verify the user id, not just the email string.
8. **Household cross-visibility unproven** — both have the search, but seeing each other's
   saves/notes/likes is unbuilt/unverified (Zach's explicit want).
