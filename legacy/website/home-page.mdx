## The one idea: shelves are DATA, not code

The home page is a stack of **shelves** — each a row of listing cards ("Homes in Overland Park", "Homes on
land"). Every shelf is a **row in `hl_home_shelf`** (web DB), not a component: its query (`queryEnvelope`),
its display knobs (`displayOptions`), its order (`sortOrder`), and its on/off (`isActive`) all live in the
row. **Adding a shelf = INSERT a row** (edit `prisma/seed/home-shelves.ts`, `npm run db:seed`) — you never
edit `HomeRows.tsx`.

Current live set (14 rows, all active): `hero` · `popular-homes` (see below) · `all-kc-metro` · 10 city
shelves (Overland Park, Leawood, Olathe, Lenexa, Shawnee, Kansas City, Lee's Summit, Liberty, Independence,
Blue Springs) · `acreage`. (The old `featured` shelf is retired.)

  Popularity sorts on the engagement counts `ListingStats` holds (views · saves · likes · shares),

  same night (ruling #257.327, Option 1: curation columns on `ListingStats`, weighted toward high-end

  **in flight, not yet live**; today's shelf (`sortOrder 8` in `hl_home_shelf`) still runs the interim
  `homesForYou` sort (photo-richness + freshness) plus `lib/home/area-rows.ts`'s `selectPriceSpread()`
  price-band guarantee (at least 3 of the final 12 priced above the metro's live 80th-percentile list
  price, at least 3 below the live median, queried fresh on every render) until the signed engagement
  sort lands.
- **The Myli band** (`components/home/MyliShowcaseCard.tsx`, the ez-shaped showcase card) — one full-width

- **One thread per browser tab.** Before this pass, three taps of the same pill in one tab opened three
  separate conversations (`HomeExperience` minted a fresh Myli-chat instance on every entry). Now the
  modal keeps the same conversation id across repeated opens in the same tab; a brand-new tab or window
  still opens a clean thread (no sessionStorage carried over — the second-window law).

## Composition pipeline

| Piece | File | What it does |
|---|---|---|
| Shelf composer | `lib/home/composer.ts` | Reads active `hl_home_shelf` rows (sorted), runs each `queryEnvelope` through the ONE search engine (`searchListings`), slices to the card count. Newest-first, no shuffle (Zach 2026-05-21: "the N newest — that's how they filter in and out"). |
| Card count | `displayOptions.maxCards` → `queryEnvelope.limit` → 15 | `maxCards` is honored as the per-shelf cap (wired 2026-07-06 — it was decorative before). |
| Hero composer | `lib/home/hero-composer.ts` | Its own path because the hero has 3 extra concerns: curated `FeaturedListing` admin overrides lead the rotation · cookie-aware rotation (`hl_seen_hero` — returning visitors see fresh slides) · a stricter photo bar (`photos.min` ≥ 25 in the hero row's envelope). |
| Hero slide count | `displayOptions.slideCount` on the `hero` row | DB-first (wired 2026-07-06): explicit caller override (mobile passes 1) > the hero row's `slideCount` > 5. No more hardcoded constant. |
| Inspiration links | `components/communities/InspirationLinks.tsx` ← `hl_inspiration_city` (24 rows) + `hl_inspiration_category` (5 rows), seed `prisma/seed/inspiration.ts` | City + category tabs. Category hrefs MUST use real `url-to-query` params — an unknown param silently drops and the tab renders the whole grid (fixed 2026-07-06: `minYearBuilt`, `oh=1`, `sort=viewsDesc`). |
| Market band | `components/market/LiveHousingDataSection.tsx` ← `MarketSnapshot` | County market snapshots. |
| Header / Footer | `components/site/Header.tsx` / `Footer.tsx` | 3-region desktop header + mobile variants; the footer is the recurring blue band (below) over the MLS GRID / Heartland IDX disclosure. |
| SEO tail | `components/home/HomeSeoTail.tsx` ← `lib/home/seo-tail.ts` | The five link shelves below the Myli band (below). Replaced the "Explore areas" tile row 2026-09-08. |

## The SEO tail — five link shelves (#257.338 §3, #257.339, #257.340)

The bottom of the home page is a link surface, not a widget: **every anchor is in the served HTML at
all times** so a crawler sees the whole set, and the overflow is hidden with `hidden` rather than
sliced out of the array. That single difference is what makes it an SEO tail. Measured on the served
page, 2026-09-08:

| Block | Links | Destination | Source |
|---|---|---|---|
| Popular home searches | 24 | `/kansas-city/<facet>` | `metroFacets()` — lane A's `lib/seo/facet-registry.ts`, never a second slug list |
| By city | 134 | `/{state}/{county}/{city}` | the geo directory (`lib/geo/geo.ts`) |
| In popular markets | 52 | `/{state}/{county}/{city}/n/{sub}` | the most-listed neighborhoods JOINED to the city's curated subdivisions, so every link resolves by construction |
| In nearby postal codes | 172 | `/{state}/{county}/{city}/{zip}` | the geo directory's zip records |
| By county | 8 | `/{state}/{county}` | all shown, no shelf, the last block |

- **The shelf pill prints `items.length`, never a number from a spec.** A label naming a count the
  list does not contain is the first thing a reader counts. (The spec said 205 zips; the geo source
  holds 172, so the pill says 172.)
- **The headings are two-tone** (`components/home/SectionHeading.tsx`): a small brand-blue kicker
  over a big `--hl-blue-dark` (#1B3A8A) phrase. Zach's redline: *"too blue — a pop of blue, not the
  whole thing."* Never black.
- **The facet links use "in Kansas City", not "Kansas City Metro"** — the link text must equal the
  `<h1>` of the page it opens (the drawing's ruling #1, and the cage's `TITLE_ECHOES_H1` one level up).
- **`popular markets` cannot be curated by hand today.** The neighborhood route resolves a slug only
  against a city's curated subdivisions or a `hl_geo_weekly_report` row, and there are ZERO of the
  latter; only 2 of the 8 KC districts are curated subdivisions, and only 4 of the wireframe's 12
  drawn names exist anywhere (one of them resolving to a different town's identically-named
  subdivision). Hence the derived list. Curating a real shortlist is a data job.

## The recurring footer (#257.338 §4)

`components/site/Footer.tsx`, on every page. The blue band is `--hl-blue-dark` (#1B3A8A — the
lighter navy, explicitly *not* `--hl-navy` #0A1128), carrying the logo mark + wordmark, "The smarter
way home", a big centered search bar that is **the same `SearchAutocomplete` the hero renders** (one
submit road per page, never a second bar), four `<h4>`-labelled columns, and the legal line
"HouseLoop · Kansas City, Missouri · MLS GRID". The required Heartland / MLS GRID disclosure block
renders below it, unchanged, and keeps its `showSoldPriceDisclaimer` opt-out.

- **Featured locations are DERIVED** from `topCitiesMetro`, not typed. A hardcoded menu list fails
  `npm run drift-check` by design — which cities we feature is a product decision, not a literal.
- **Six drawn links are deliberately absent** because they have no page: About us · Refinance
  calculator · Accessibility · DMCA notice · Real estate licenses · Fair housing. A dead nav item is
  worse than an absent one, and in a recurring footer it is dead on every page of the site. DMCA
  instead points at the MLS GRID notice address the disclosure already carries. **Fair housing and
  Real estate licenses are flagged to the desk as possible required disclosures rather than dropped
  silently**; the same flag covers the brokerage name still present in the IDX block, which
  #257.339 asks to remove and the license may require.

## Global constants — `hl_app_config`

Product constants a non-engineer might change live in `hl_app_config` via `lib/config/config-service.ts`
(typed accessors, 5-min cache). **Every key has a real consumer** (dead keys purged 2026-07-06):

| Key | Consumer |
|---|---|
| `lot.sqft_per_acre` / `lot.max_sane_acres` | acreage math + outlier defense |
| `cache.active_ttl_seconds` (6h) | `getListing` freshness for active listings |
| `cache.pending_ttl_seconds` (1h) | per-status TTL — pending/under-contract refreshes faster (about to close) |
| `sync.*` | runtime watermarks (not user-facing) |

## Drift defense (why this stays clean)

- ESLint `no-magic-numbers` + `no-restricted-imports` (provider wire types die in `lib/listings/providers/`).
- `npm run drift-check` full-tree grep audit + `tools/houseloop-prisma-check.sh` — both run on pre-commit for HouseLoop files.
- The 5-question decision tree in `apps/houseloop-web/AGENTS.md` — read it before adding anything here.

## Known absent (flagged, not built)

- **Geo personalization** — every visitor sees the identical shelf order; `sortOrder` was built to support
  per-visitor ordering when we want it.
