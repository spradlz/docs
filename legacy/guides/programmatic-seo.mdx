HouseLoop's organic-search engine is a programmatic web of indexable pages: every active
listing as its own readable URL, plus a directory tree of **county → city → zip → neighborhood**
landing pages. Every page is server-rendered from live inventory, carries Schema.org
structured data, and is listed in the sitemap so Google can discover it.

| Surface | URL shape | Status |

| City landing | `/{state}/{county}/{city}` | **Live** |

| GSC data in CRM | CRM → Settings → Website → SEO | **Live** - clicks, impressions, avg position via DWD SA |
| Schema.org JSON-LD | Site-wide `@graph` in root layout | **Live** - WebSite + SearchAction + SiteNavigationElement |
| Listing FAQ (stored, per-listing) | `Listing.faq` jsonb, `/home/{slug}/{hlid}` | **Live (2026-09-08)** - `FAQPage` JSON-LD, refreshed by Inngest, 0 of 17,006 active/pending listings missing one |
| MCP server for AI agents (ChatGPT etc.) | `houseloop.ai/api/mcp` | **Live (2026-09-08)** - see "The MCP server" below |
| `llms.txt` | `houseloop.ai/llms.txt` | **Live (2026-09-08)** - site summary + MCP pointer for LLM crawlers |
| Blog author identity (E-E-A-T) | `/blog/{slug}` | **Live (2026-09-08)** - JSON-LD `author` is a named Person, not the org; visible byline on every post |

The `/n/` prefix on neighborhoods is deliberate — it avoids colliding with the `[zip]`
segment one level up.

## The Monday pipeline

Every Monday starting at 12:01 AM Central, six Inngest crons fire in sequence. Each one
depends on the previous step's output, so they're staggered 30-60 minutes apart:

```
05:01 UTC (Mon 12:01 AM CT)  Stats engine (geo-weekly-report) → sold/flow/window/FAQ/narrative per geo
RETIRED (2026-07-06): the standalone Monday article writer is gone — per-tier page builders write the LLM narratives at build time (week 2026-06-29: 8/8 county · 72/72 city · 134/134 zip · 738/837 nbhd narrated)
06:00 UTC (Mon  1:00 AM CT)  County page builder → hl_geo_page (8 counties)
07:00 UTC (Mon  2:00 AM CT)  Zip page builder → hl_geo_page (~205 zips)
08:00 UTC (Mon  3:00 AM CT)  City page builder → hl_geo_page (~134 cities)
09:00 UTC (Mon  4:00 AM CT)  Neighborhood page builder → hl_geo_page (~5,500 neighborhoods)
```

The pipeline completes by ~5:00 AM CT. Crons survive Railway deploys via auto-registration
on boot (see [SEO pipeline](/guides/seo-background-jobs#auto-registration-on-boot)).

See [SEO pipeline — every Inngest job](/guides/seo-background-jobs) for the full reference,
including the daily stats crons, event-driven functions, and operating procedures.

## Coverage

The 8 Core Heartland counties (Jackson, Johnson, Clay, Cass, Platte, Wyandotte, Leavenworth,
Miami) → every real city → neighborhoods per city → every zip → every active listing.

The directory tree comes from one taxonomy file (`lib/geo/heartland-geo.generated.json`),
rebuilt by `scripts/build-geo-taxonomy.ts`. As of June 2026: **8 counties, 134 cities,
205 zips, 5,524 neighborhoods = 5,871 geo pages** + every individual listing.

## Page anatomy (geo + neighborhood pages)

1. **H1** — `"{Place}, {ST} Real Estate & Homes For Sale"` (Zillow phrasing, one line).
2. **Result count + sort**, filter bar, listing cards, map toggle.
3. **Breadcrumb trail** — `For Sale: Kansas > Johnson County > Overland Park` at the top of the SEO block (`BreadcrumbList` JSON-LD).
4. **Market Trends hero** — 8-card grid from `hl_geo_market_stats` (homes for sale, median sale price, sold 12mo, $/sqft, sell-to-list, days to offer, coming soon, under contract). Anchored at `#market-trends`.
5. **Weekly article** — LLM-written narrative + deterministic FAQ from `hl_geo_weekly_report`. Updated every Monday.
6. **The SEO section** — rendered dynamically by `LocationSeo`: Find a Home You'll Love (amenity), Select Property Type, Popular Searches, Nearby City Homes ($), Neighborhood Homes ($), Homes by Zip ($), Estimate Sale Proceeds, More to Explore (price bands).
7. **Compliance footer** (see below).

## Schema.org structured data

The root layout (`apps/houseloop-web/app/layout.tsx`) includes a JSON-LD `@graph` with:

- **WebSite** — `name: "HouseLoop"`, `url: "https://houseloop.ai"`, with a `SearchAction`
  pointing to `/listings?q={search_term_string}` (enables Google Sitelinks Searchbox).
- **SiteNavigationElement** — 5 top-level nav items (Buy, Sell, Market Data, About, AI Search)
  for Google to understand the site structure.

Individual listing detail pages add their own `RealEstateListing` JSON-LD with property details.

## Compliance — non-negotiable

<Warning>
**Aggregate sold stats ARE permitted** at neighborhood / zip / city / county level per
Heartland IDX Rules section 15. Only **per-address** sold price is restricted (section 12.3b) — relevant only to
the individual listing detail page.
</Warning>

- Per-page Heartland MO/KS disclosure: "Listings courtesy of Heartland MLS, distributed by MLS GRID."
- Per-listing brokerage + MLS# + "courtesy of Heartland MLS as distributed by MLS GRID."
- No seller PII; honor address-withhold; same-brand site; no framing.
- Dynamic filtered search URLs (`/listings?minPrice=...`) are **not** indexed — only the clean
  canonical landing pages are.

## URL scheme

```
Listing detail   /home/{canonicalSlug}/{HLID}            e.g. /home/4607-olive-street-kansas-city-mo-64130/HLID101234 (old /listings/... + address-only forms 301 here)
County           /{state}/{county}                       e.g. /kansas/johnson-county
City             /{state}/{county}/{city}                e.g. /kansas/johnson-county/overland-park
Zip              /{state}/{county}/{city}/{zip}           e.g. /kansas/johnson-county/overland-park/66210
Neighborhood     /{state}/{county}/{city}/n/{slug}        e.g. /kansas/johnson-county/overland-park/n/wild-horse
```

Legacy `/listings/{hlid}/` is a permanent 301 to the canonical readable URL, so every link
Google already crawled keeps its equity.

## The SEO Overview dashboard (CRM)

The CRM page **Settings → Website → SEO → Overview** is rendered server-side and fetches
`GET houseloop.ai/api/seo/overview` (the CRM always reads the **production** website API, even
on localhost — `NEXT_PUBLIC_HOUSELOOP_WEB_URL` defaults to `https://houseloop.ai`). The endpoint
reads `hl_seo_artifact_log` and returns three things:

| UI element | Source field | Counts |
|---|---|---|
| KPI cards (clicks / impressions / rank) | GSC (see above) | 30-day GSC totals |
| **"Articles by type"** cards | `COUNT(*) GROUP BY level` | every artifact, all-time, per geo level |
| **"Articles published per week"** stacked bar | `date_trunc('week', "createdAt")` | artifacts grouped by the week they were **generated** |

<Note>
**The weekly chart buckets every level by `createdAt` (generation date) — not `weekStart`.**
A geo article's `weekStart` is the *market-stats week the article is about*, which a single
Monday generation run backfills across many historical weeks. Bucketing the chart on `weekStart`
made one run scatter into earlier bars (a 6/8 run with 1,888 neighborhood articles showed up under
the 6/1 week, leaving the 6/8 bar showing only that week's houses). The chart means "articles
**published** per week", so it buckets on `createdAt` and a run shows as one stacked bar — matching
what the Run Log shows for that day. A "coverage by stats-week" view (gaps in market-week coverage)
would be a *separate* chart keyed on `weekStart`; it is not built.
</Note>

Code: `apps/houseloop-web/app/api/seo/overview/route.ts` (endpoint) +
`apps/houseloop-crm/app/(crm)/settings/website/seo/page.tsx` (chart render).

Each stacked-bar number is a link: clicking it opens the **SEO Run Log** filtered to exactly
those articles — `/settings/website/seo/run-log?level=<level>&week=<YYYY-MM-DD>`. The Run Log
(`SeoArtifactBrowser`) reads `level` + `week` from the URL, shows a "week of …" chip with a
clear button, and the artifacts endpoint's `week` filter buckets by `createdAt` week so the
filtered row count matches the bar segment (e.g. neighborhood / week of Jun 8 → 1,888 rows).

## The MCP server — how ChatGPT and other AI agents read HouseLoop (shipped 2026-09-08)

`houseloop.ai/api/mcp` is a Streamable HTTP [Model Context Protocol](https://modelcontextprotocol.io)
server (`apps/houseloop-web/lib/mcp/houseloop-mcp-server.ts` + `app/api/mcp/route.ts`) — a second,
purpose-built server alongside the existing internal STDIO one (`tools/mcp/houseloop-search-server.mjs`,
used by agents in this repo, not reachable by ChatGPT). It exposes four read-only tools, each reusing
an existing reader rather than recomputing anything:

| Tool | Reads | Returns |
|---|---|---|
| `search_homes` | `searchListings` / `parseSearchParams` | matching listings |
| `home_facts` | `getListing` | beds/baths/sqft, price, status dates (coming-soon/pending/sold), the FAQ |
| `market_stats` | `resolveListingMarketStats` | sell-to-list %, sold count, median $/sqft for the area |
| `home_value` | `Listing.houseLoopValue` | the HouseLoop estimate + range |

Every result carries `source: "HouseLoop · Heartland MLS"`, a `dataSource` attribution string
("Heartland MLS data distributed by MLS GRID"), a `brokerage` field, and an absolute URL back to the
canonical `/home/{slug}/{hlid}` page — nothing is returned that isn't already public on that page. The
server calls itself "Myli by HouseLoop" to ChatGPT. `robots.txt` explicitly allows the AI crawlers
(`OAI-SearchBot`, `GPTBot`, `ChatGPT-User`, `ClaudeBot`, `PerplexityBot`, `Google-Extended`) as a
recorded decision rather than an accident of the wildcard allow.

Proof: `node tools/seo/mcp-smoke.mjs <url>` — a real MCP client that calls all four tools and asserts
each result carries an item + source + URL.
