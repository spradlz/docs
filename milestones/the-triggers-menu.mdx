# ⭐ The Triggers Menu

**Milestone completed August 18, 2026.** [Floor 2 on the board](/master-plan/floor-2)

---

## What this is

There is one page in the CRM that answers the question *"what actually happens when something
happens?"* It used to be unreadable. It showed raw rules - the plumbing - so the only people who
could understand it were the people who wrote it.

Now it shows the **events themselves**, grouped by where they come from, each one a plain-English
row you can switch on or off.

Your own words on this, from back in July: *"My Trigger Events page already IS this page. Un-filter
it and add one Trigger column."* That is what shipped.

## The written detail

- [The activity vocabulary guide](/guides/activity-catalog) carries the spec for this page - the
  section on where it sits in the menu, and the ruling that this is **one page, not two**.

## The walkthrough

### You open Automation Triggers

Ninety-five events, grouped by where they come from. The pills across the top are the sources: the
website sends twenty-two, **Follow Up Boss sends twenty-eight**, transaction coordination sends
seven, the inbox sends thirty-eight.

![The triggers menu - ninety-five system events grouped by source, with Follow Up Boss holding twenty-eight of them](/images/milestones/the-triggers-menu/triggers-menu.png)

Each row tells you five things at a glance: what the event is, whether it is switched on, whether it
creates a lead, what automation it starts, what notification it sends, and how many times it has
fired.

### You click a row, and it opens up

Expanding an event shows you what it actually drives - the workflow or playbook attached to it. No
second screen, no hunting.

![One event expanded, showing the workflow and playbook it drives](/images/milestones/the-triggers-menu/triggers-menu-expanded.png)

### The part that mattered most

We walked this page **on the deployed site**, row by row, rather than reading the code and assuming.
That distinction is the whole reason this milestone is signed. Code that looks right and a page that
is right are two different claims, and only one of them is the one you actually use.

## What you can do with it

| What you do | What happens |
|---|---|
| Open Automation Triggers | Every event the system can react to, grouped by where it comes from |
| Click a source pill | The list narrows to just that source's events |
| Toggle an event off | We stop reacting to it - and the row says so |
| Expand a row | You see the workflow or playbook that event starts |
| Read the fired count | The real number of times that event has arrived |
| Switch to Custom Triggers | The rules your team wrote by hand, kept separate from the built-in events |
