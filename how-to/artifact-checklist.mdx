# What the skill does

Every agent runs their project as **ONE board**: a permanent numbered list with a single green
**Active Working Section** that items are pulled into and dropped back out of. Zach reads these on a
vertical screen all day — the board *is* the session.

| It gives you | Which fixes |
|---|---|
| **One permanent list, 1 → ∞** | "item 34" meaning something different tomorrow |
| **One green active section** | not knowing what is being worked *right now* |
| **A ten-field audit before anything ticks** | "done" meaning "it compiled" |
| **The record band** | the law and the findings getting lost between checkboxes |
| **The reference band** | sub-artifacts and locked wireframes floating unattached |
| **A hook onto the task list** | the board going stale because someone forgot to update it |

# How to invoke it

```
/project-board                      rebuild + republish, report the counts
/project-board new <name>           scaffold a new board for a project
/project-board active 56,72,94-101  pull those items up + create the matching tasks
/project-board done 56              move back down, green, date — REFUSES without an audit
/project-board audit 56             write the ten-field receipt
/project-board loop                 work the whole active section end to end
/project-board migrate <old.html>   convert an existing hand-built board (parses + diffs)
```

**The one you will use most is `/project-board loop`.** Name the items you want worked, then say loop,
and the agent works every one of them — build, walk it in Playwright, write the audit, tick it,
republish — without checking in between items.

<Warning>
**What is automatic, stated honestly.** ✅ Marking a task complete rebuilds the board — a `PostToolUse`
hook does it, with no agent judgement involved. ⚠️ **Publishing is not automatic**: a shell hook cannot
call the Artifact tool, so the hook writes a dirty marker and the `UserPromptSubmit` hook surfaces it
every turn until the agent republishes. **Never call this live bidirectional sync** — it is a
derivation plus a nag, and claiming more is the class of overstatement this protocol exists to stop.
</Warning>

````markdown
# The project board

**One agent, one board, ONE permanent numbered list, ONE green active section.** Zach reads these on a
vertical screen all day — the board IS the session. If a decision is not on it, it did not happen.

## Why this is a skill and not a doc

A doc is read *if the agent thinks to read it*, so every agent re-interprets the layout and you get four
different boards. **This skill ships the generator**, so the layout is not described — it is executed.
An agent never writes the HTML. It edits `board.json` and runs the tool. That is the whole point:
**zero interpretation surface.**

## The five bands, in this order, always

| Band | What is in it |
|---|---|
| 🟢 **Active working section** | The items being worked *right now*, pulled up out of the list, with the PRD covering every one of them |
| **The list** | Everything, 1 → ∞, permanent order. Ticked items stay exactly where they are. |
| **The record** | The law, the corrections, the findings. Everything that is reasoning rather than a task. |
| **Reference** | Every sub-artifact this board points at: locked wireframes, competitor references, linked artifacts |
| **Audit results** | The receipts. Last, because it is the longest band and nothing should sit under it. |

There is deliberately **no "Completed" section** — a finished item stays in its own position and goes
green. A second pile is a second ordering, and two orderings is how a board splits in half.

The nav **scrolls**, it does not hide: one page, end to end, with a scrollspy.

## ⭐ A BOARD THAT NAMES A WIREFRAME MUST **SHOW** IT

> Zach, 2026-08-04, reading the saved-search board: *"It says 'wireframe locked'… I need to actually
> see that visually with screenshots. There's no reference — the reference just says 'reference and
> wireframes', but it doesn't actually give me the wireframe. **That artifact IS the wireframe for
> that section, dude.**"*

**The Reference band is where a design LIVES, not where it is described.** A name, a file path and a
link are text *about* a picture. An artifact cannot read the filesystem, so `docs/wireframes/x.html`
renders as literally nothing a human can look at, and a link costs a second click and the right login.

**The rule:** every entry in `reference.wireframes` carries a **`shot`** (and a `shotMobile` when the
design has a phone view). It is inlined as an image, full width, exactly like a receipt screenshot.

```bash
node .claude/skills/project-board/shoot-wireframe.mjs docs/wireframes/<file>.html \
     --out .claude/reports/<board>/wireframes --name "The thing — LOCKED <date>"
# prints a paste-ready JSON block carrying "shot" + "shotMobile"
```

**The build FAILS (exit 1) on a named wireframe with no picture** — same treatment as a missing
receipt screenshot, and for the same reason: *a board whose evidence is invisible is a claim with the
evidence torn out.*

### Declaring a gap is allowed. Faking one is not.

Some designs were signed off and never saved into the repo, so there is no file to render. Say so:

```json
{ "name": "…", "what": "…", "status": "SIGNED OFF · not in the repo",
  "gap": "The HTML was never committed — that is open item 23. Until it closes this board can only
          describe the wireframe." }
```

That renders an **amber MISSING card** and passes the gate. The gate catches *silence*, not honesty —
without this escape the only way to get a green build would be to fake a picture, which is the exact
thing it exists to stop. An empty band is fine. **A false promise is not.**

### Two defects underneath this, both worth remembering

1. **Nothing in the shared generator may be one board's specifics.** The two Reference sub-headings
   were hardcoded — `"a competitor's portal, desktop and mobile"` is true of the Seller Engine board,
   which is what the generator was written against. Every *other* board inherited that sentence and
   promised Zach things it did not have. (The output filename had the same bug ten lines away: any
   `board.json` built itself into `seller-engine-board.html`.) **A heading is content; content lives
   in the board's own JSON.** Same class as a hardcoded allowlist.
2. **An empty sub-band must render NOTHING.** A heading over emptiness reads as *"the thing is here"* —
   worse than a blank page, because a blank page sends you looking and a false heading makes you stop.

## ⭐ THE NUMBER IS PERMANENT

Assigned once, never changed. "Item 34" means the same thing tomorrow and in a message to another agent.
New work appends at the end. Re-prioritising does **not** renumber. Gaps are fine; renumbering is not.

> This REVERSES an older law that derived numbers from DOM position. That was wrong: a number whose
> meaning silently drifts when something is inserted above it is not an identifier, it is a coincidence.

## ⭐ The active working section

**Exactly one, green-banded.** Two green blocks means two "now"s and neither is real.

1. Zach names items — one, or a range: *"make 56, 72, 89 and 94 through 101 active."*
2. Each is **pulled up** into the active section and leaves a dashed **placeholder** in its home position,
   so the list never develops holes and you can always see where an item went.
3. Done → it **moves back down**, goes green, gets its checkbox, its **completion date**, and a link to
   its audit.

Active can be one item or a hundred — it is a batch on purpose, because that is what makes `/board loop`
a real instruction instead of a per-item conversation.

**The PRD covers EVERY item in the active section.** Not a summary of the theme — the reasoning for each,
including what was rejected and why. An item without its reasoning is one someone rebuilds wrong later.

## ⭐ THE BOARD IS TIED TO THE TASK LIST — STRUCTURALLY

> Zach 2026-08-04: *"make it structural and not you need to think to update the board — the board has to
> be tied to the task list."*

**The task list is a RENDERING of the active section, not a second system that gets reconciled.** They
cannot drift because one derives from the other.

| | |
|---|---|
| `/board active 56,72` | writes `board.json` **and** creates the tasks, in one action |
| task marked `completed` | a `PostToolUse` hook regenerates the board — **no agent judgement involved** |
| task title | always carries the item number: `#56 Retire platform='inbox'` — that number is the join key |

**What is genuinely automatic, and what is not — stated honestly:**

- ✅ **Automatic:** marking a task complete rebuilds `board.json` + the HTML, via `tools/hooks/board-sync.sh`.
- ⚠️ **Not automatic:** publishing to the artifact URL, because a shell hook cannot call the Artifact tool.
  The hook writes a **dirty marker**; the `UserPromptSubmit` hook surfaces it every turn until the agent
  republishes. Same anti-forget mechanism this repo already uses for progress and identity.

**Never claim live bidirectional sync.** It is a derivation plus a hook, and saying otherwise is the kind
of claim this whole protocol exists to stop.

## ⭐ The audit — ten fields, and nothing is ticked without one

> Compiling is not evidence. Typechecking is not evidence. A passing gate is not evidence. The receipt is.

1. **Walked in Playwright** — the literal click path, real headed Chrome
2. **Buttons actually pushed** — not "the button exists"; it was clicked and something happened
3. **What happened on the page** — embedded screenshot + one human sentence
4. **The table it wrote to** — every table touched, named
5. **The event logged** — the activity kind. **"No row" is a FINDING, not a blank.**
6. **The variables that moved** — real values, before and after
7. **The code it wrote to** — the files
8. **Against the schema lock?** — tables vs `schema.lock.json`, kinds vs the catalog **and writability**
9. **Is it inventing something new?** — a new table/kind/column gets signed before it ships
10. **Reuse check** — did you look for something already built? Name what you found and why it did not fit

Field 8 is the one people skip: a kind can be in the catalog and still have its writes rejected silently
because it was never seated. **Presence is not writability** — probe it, then roll back.
Field 10 is the anti-drift field: most duplicate components exist because nobody wrote that line down.

## The state lives in DATA

```
<board>.json                                ← the state: items, status, dates, PRD, record, reference
.claude/skills/project-board/build-board.mjs ← the generator
<board>.html                                ← the output, published as the artifact
```

**Never hand-edit the HTML.** The previous board reached 3.7MB and 203 items by accretion — two competing
"today's work" sections, a stale date, two numbering schemes — precisely because the state lived in the
markup and moving an item meant surgery. With the state in JSON it is a one-line edit.

**And when you restructure a board: MIGRATE it, never retype it.** Parse the old document and diff the
result — measure the percentage of fragments carried across and report the number. Rebuilding from memory
silently drops the reasoning, which is the half nobody notices is gone until they need it.

## ⭐ MIGRATING AN EXISTING BOARD — the protocol

**Every agent with a hand-built board migrates it with the script, never by hand.**

```
node .claude/skills/project-board/migrate-board.mjs <old-board.html> <out-board.json> \
     --owner <agent> --title "<name>"
```

It parses the old document, writes `board.json`, extracts embedded screenshots back into real files,
**diffs the result, and REFUSES to pass below 99%** — printing exactly which fragments did not make it.

### The five rules, each one earned

1. **PARSE, NEVER RETYPE.** Rebuilding a board from memory is how ~130 items, 16 screenshots and every
   law/correction/finding section went missing on 2026-08-04. The file was never deleted — but the
   published artifact lost them, and from Zach's side that is identical to deleting them.
2. **NO CAPS ANYWHERE.** Three of mine ate content, each hiding the next: `paras[:6]` cut the fourteen
   locked build decisions (they are paragraphs 5–14); a 2000-char truncation cut the **tails**, which
   is exactly where the laws live; and a head-match `continue` skipped whole list bodies. The script
   has none.
3. **MEASURE, DO NOT CLAIM.** The gate is a number. If it says 96%, you are not done — read
   `<board>.missing.txt` and fold it in. *A verification gate that under-reports is worse than none*,
   which is why the comparison strips tags and normalises entities before comparing (`<code>hl_leads</code>`
   must match plain `hl_leads`, `2&ndash;9` must match `2–9`).
4. **OPEN EVERY RECOVERED IMAGE.** Each lands with `review: "OPEN THIS AND WRITE ITS CAPTION"`. I binned
   a competitor's MOBILE reference shot **twice** by pattern-matching its caption instead of looking at
   it. An image with no caption is not a duplicate — it is an image with no caption.
5. **KEEP THE ORIGINAL FILE FOREVER.** It is the only thing that makes the diff possible, and the only
   way to recover if the migration is wrong.
6. **⭐ THE COMPLETENESS SCORE IS TWO NUMBERS, NEVER ONE — TEXT AND IMAGES.** The gate used to count
   text fragments only, and I reported its **100.0%** as *"nothing was lost."* Images are not text
   fragments, so that score was perfectly compatible with losing **every picture on the page** — which
   is what Zach found. The check answered *"did the prose survive?"* while I reported it as *"did the
   artifact survive?"* — the green-signal failure
   (`.claude/lessons/every-tool-answers-a-narrower-question.md`) **inside the verification tool
   itself**, written the same afternoon we documented it. The migrator now always prints both:

   ```
   COMPLETENESS (text):   765 fragments · 639 carried · 126 missing → 83.5%
   COMPLETENESS (images): 11 in source · 11 carried
   ```

   A single blended percentage is precisely how a lost picture hides behind carried prose. **Two
   questions, two numbers.** It also names any `<img src="https://…">` it cannot recover (it can only
   extract *embedded* data-URI images) instead of skipping them silently, and it warns when the source
   **talks about** a wireframe while `reference.wireframes` is empty — the exact shape of this bug.

### What the numbers become

Migration is the **one moment** numbers are assigned. Old inline prefixes (`12 · Do the thing`) are
stripped — they came from a scheme that no longer exists and would collide. From that moment the
number is permanent.

### After it passes

1. Caption every recovered image, then sort them into `reference.shots` or delete the receipt duplicates.
2. **Fill in the Reference band before you publish** — it is the band a migration leaves empty, and an
   empty Reference band is the one people notice. Every wireframe gets a **`shot`** (or a declared
   `gap`); every competitor/reference capture gets a real caption written **after opening the image**.
   Set `wireframesLede` / `shotsLede` to what *this* board actually holds — never leave another
   board's sentence describing yours.
3. Move the genuinely-still-open items to `status: future`; everything shipped stays `done`.
4. Set `active` to the batch you are working now, with a PRD line per item.
5. Run the generator, publish, and **say BOTH completeness numbers out loud** in the handoff — text
   and images. Reporting one number when the tool measured two is how this bug shipped.

## `/board loop` — the protocol

For each item in the active section, in order:

1. **Read its PRD line.** No PRD is a bug in the board — write it first.
2. **Build it.**
3. **Walk it in Playwright.** Headed Chrome, real clicks. `curl` is never a substitute for a walk.
4. **Write the ten-field audit.** If any field cannot be filled honestly, the item is not done.
5. **`/board done <n>`**, then **republish**. Zach is reading it while you work — a board that only
   updates at the end is one he cannot use to interrupt you.

**If a walk reveals the item was standing on something broken:** that is not a detour, it is a new item.
Append it at the end with its own number and say so. **Never silently widen an item's scope** — the number
is a contract about what got done.

## The rules that keep it honest

- **Report what happened, not what you intended.** A failed walk gets a receipt saying it failed.
- **Corrections stay on the record** — in the item's note and in The record band. A board with no
  corrections is a board nobody audited.
- **One owner per item.** Two agents needed means two items; an item with two owners has no owner.
- **Never fake a control.** A button that writes nothing must say so on its face.
````

## 2 · `.claude/skills/project-board/build-board.mjs` — the generator

**This is the file that makes the standard un-driftable.** The agent never writes HTML; it writes
`board.json` and runs this. Pass a board path as `argv[2]` to run it for any project.

```js
#!/usr/bin/env node
/**
 * build-board.mjs — render the master board from board.json. THE ONE generator for this page.
 *
 * ⚑ CATALOG / REUSE CHECK, answered rather than skipped. The pre-build gate offered four cataloged
 * tools (footage-landmark-scan, ops-card-create, engagement-dashboard, railway-deploy-status) — none
 * render a checklist. The real reuse question was `build-receipts.mjs`, which I own and which wrote
 * into THIS SAME FILE. Two tools writing one page is precisely the drift we keep fighting, so this
 * one ABSORBS its screenshot-inlining (the sips → JPEG data-URI routine below is lifted from it) and
 * becomes the single writer. build-receipts still serves the older artifacts.
 *
 * ⚑ WHY A GENERATOR AND NOT A HAND-EDITED PAGE. The previous board reached 3.7MB and 203 list items
 * by accretion: every session appended, nothing was reorganised, and it ended with TWO overlapping
 * "today's work" sections, a stale date, and two numbering schemes that did not reconcile. Zach,
 * 2026-08-04: "this thing is a shit show, dude." The cause was structural — the STATE lived in the
 * HTML, so moving an item meant surgery on markup. Now the state is board.json and the page is a
 * render of it: pulling item 56 into the active section is a one-line data edit.
 *
 * THE ARCHITECTURE (Zach's, dictated 2026-08-04):
 *   · ONE list, 1 → ∞. THE NUMBER IS PERMANENT — items are never renumbered, so "item 34" means the
 *     same thing tomorrow as it does today.
 *   · Items MOVE. Pulling one into the active section leaves a PLACEHOLDER in its home position, so
 *     the list never develops holes and you can always see where it went.
 *   · ONE active section, wearing a big green band. It can hold a single item or a hundred — batch,
 *     so it can be looped.
 *   · The PRD covers EVERY item in the active section. No item in there without its reasoning.
 *   · Finishing moves an item back DOWN to its own position, greens it, and stamps the date.
 *   · Three sections + sticky jump nav: ACTIVE · THE LIST · AUDIT RESULTS. There is deliberately no
 *     "completed" section — a finished item stays where it belongs and is simply ticked.
 *
 * Usage: node tools/houseloop-cards/build-board.mjs
 */
import { readFileSync, writeFileSync, existsSync, statSync } from 'fs';
import { execFileSync } from 'child_process';
import { join, basename, dirname } from 'path';

const ROOT = '/Users/zachspradling/Code/BossLoop-Gold';
// ⚑ ANY BOARD, NOT JUST THIS ONE. The skill ships one generator for every agent's board; pass the
//   json path as argv[2] (and the html out as argv[3]) or fall back to the Seller Engine default.
const BOARD = process.argv[2] || `${ROOT}/.claude/reports/board.json`;
// Per-board receipts dir (board.json `receiptsDir`, repo-relative) — boards must not share one
// manifest or board A's receipts render in board B's audit band. Falls back to the original default.
const RDIR_DEFAULT = `${ROOT}/.claude/reports/receipts`;

const board = JSON.parse(readFileSync(BOARD, 'utf8'));
// ⚑ THE OUTPUT NAME COMES FROM THE BOARD, NOT FROM THE BOARD I HAPPENED TO WRITE THIS FOR.
//   This used to rewrite any "board.html" to "seller-engine-board.html" — so the saved-search board
//   built itself into a file called seller-engine-board.html sitting in the saved-search folder.
//   Same defect as the hardcoded reference headings below, ten lines apart: one board's specifics
//   baked into the shared generator. `slug` in the board JSON wins; otherwise the folder names it.
const OUT = process.argv[3] || (() => {
  const html = BOARD.replace(/\.json$/, '.html');
  if (!html.endsWith('board.html')) return html;
  const slug = board.slug || basename(dirname(BOARD));
  return join(dirname(BOARD), `${slug === 'reports' ? 'seller-engine' : slug}-board.html`);
})();
const RDIR = (() => { const b = JSON.parse(readFileSync(BOARD, 'utf8')); return b.receiptsDir ? `${ROOT}/${b.receiptsDir}` : RDIR_DEFAULT; })();
const receipts = existsSync(`${RDIR}/manifest.json`)
  ? JSON.parse(readFileSync(`${RDIR}/manifest.json`, 'utf8')).receipts ?? [] : [];
const receiptFor = (id) => receipts.find((r) => String(r.item) === String(id));

const esc = (s) => String(s ?? '').replace(/&/g, '&amp;').replace(/</g, '&lt;').replace(/>/g, '&gt;');

// Inline a screenshot as a data URI. An artifact cannot reach the filesystem, so a linked image
// renders as nothing at all — a receipt with an invisible screenshot is not a receipt.
function hash(s) { let h = 0; for (const c of s) h = (h * 31 + c.charCodeAt(0)) | 0; return h; }
// ⚑ A MISSING SHOT IS A BUILD FAILURE, NOT A WARNING. Counted here, enforced at the exit below.
const missingShots = [];
function inlineShot(rel) {
  if (!rel) return null;
  const abs = rel.startsWith('/') ? rel : join(RDIR, rel);
  if (!existsSync(abs)) { missingShots.push(abs); console.warn(`  ⚠ missing screenshot: ${abs}`); return null; }
  const out = join('/tmp', `board-${Math.abs(hash(abs))}.jpg`);
  try {
    execFileSync('sips', ['-s', 'format', 'jpeg', '-s', 'formatOptions', '72',
                          '--resampleWidth', '1200', abs, '--out', out], { stdio: 'ignore' });
  } catch {
    return `data:image/png;base64,${readFileSync(abs).toString('base64')}`;
  }
  console.log(`  · ${rel} → ${Math.round(statSync(out).size / 1024)}KB`);
  return `data:image/jpeg;base64,${readFileSync(out).toString('base64')}`;
}

// ── THE REFERENCE BAND ────────────────────────────────────────────────────────────────────────────
// ⚑ TWO DEFECTS ZACH FOUND HERE ON 2026-08-04, both structural, both mine (Caleb):
//
//   ① THE HEADINGS WERE HARDCODED. "The reference — a competitor's portal, desktop and mobile" is
//      true of the SELLER ENGINE board, which is the board I wrote this generator against. Every
//      OTHER board inherited that sentence verbatim, so the saved-search board promised Zach a
//      competitor's portal, a desktop view, a modal and a mobile view — and had none of them. A
//      heading is CONTENT; content belongs in the board's own JSON, never baked into the renderer.
//      Same class as a hardcoded allowlist: one place to edit, N places that silently drift.
//
//   ② AN EMPTY SUB-BAND STILL RENDERED ITS HEADING. Zero wireframes printed the heading and then
//      nothing under it, which reads as "the wireframe is here" — worse than an empty page, because
//      an empty page makes you go look for the thing and a false heading makes you stop looking.
//      A band with nothing in it now renders NOTHING, and a board that has no wireframe at all says
//      so out loud, pointed at the item that would fix it.
//
//   ③ AND THE ONE UNDER BOTH: a wireframe rendered as its NAME + FILE PATH + LINK. Text about a
//      picture. An artifact cannot read the filesystem, so `docs/wireframes/x.html` shows a human
//      absolutely nothing. A NAMED WIREFRAME MUST SHOW ITS PICTURE — `shot` (and optionally
//      `shotMobile`) are inlined the same way receipts are, and a wireframe without one is a BUILD
//      FAILURE, not a text-only fallback. Render it with: shoot-wireframe.mjs <file.html> --out …
```

```bash
#   remembering, which is the whole ask.
#
# WHAT IT DOES: fires PostToolUse on TaskUpdate/TaskCreate. If a completed task's title carries an
# item number (`#209 …`), the matching item in board.json is moved to `done` with today's date, pulled
# out of the active section, and the board is regenerated.
#
# ⚑ WHAT IT HONESTLY CANNOT DO: publish. A shell hook cannot call the Artifact tool, so it writes a
#   DIRTY MARKER at .claude/state/board-dirty and the UserPromptSubmit hook surfaces that back to the
#   agent every turn until it republishes. Same anti-forget mechanism this repo already uses for
#   progress and identity. NEVER describe this as live bidirectional sync — it is a derivation plus a
#   nag, and claiming more than that is exactly the class of overstatement this protocol exists to stop.

set -euo pipefail
ROOT="/Users/zachspradling/Code/BossLoop-Gold"
BOARD="$ROOT/.claude/reports/board.json"
GEN="$ROOT/.claude/skills/project-board/build-board.mjs"
MARK="$ROOT/.claude/state/board-dirty"

[ -f "$BOARD" ] || exit 0
[ -f "$GEN" ]   || exit 0

# The hook receives the tool payload on stdin. Only completed tasks whose title carries an item number
# matter — that number is the join key, and it always re-derives from the board, so the board wins.
PAYLOAD="$(cat 2>/dev/null || true)"
echo "$PAYLOAD" | grep -q '"completed"' || exit 0

NUMS="$(echo "$PAYLOAD" | grep -oE '#[0-9]+' | tr -d '#' | sort -un || true)"
[ -n "$NUMS" ] || exit 0

CHANGED=0
for n in $NUMS; do
  if node -e "
    const fs=require('fs'); const p='$BOARD';
    const b=JSON.parse(fs.readFileSync(p,'utf8'));
    const it=b.items.find(x=>x.n===$n);
    if(!it || it.status==='done') process.exit(1);
    it.status='done'; it.date=new Date().toISOString().slice(0,10);
    // Finishing an item also pulls it OUT of the active section — the 'move back down' half of the
    // rule. Doing it here is what stops the green band drifting out of date behind the agent.
    if(Array.isArray(b.active?.items)) b.active.items=b.active.items.filter(x=>x!==$n);
    fs.writeFileSync(p, JSON.stringify(b,null,2));
  " 2>/dev/null; then CHANGED=1; echo "  board: item $n → done"; fi
done

[ "$CHANGED" = "1" ] || exit 0

node "$GEN" >/dev/null 2>&1 || true
mkdir -p "$(dirname "$MARK")"
echo "board rebuilt $(date '+%H:%M') — items $NUMS closed. REPUBLISH the artifact." > "$MARK"
echo "  ⚑ board regenerated — republish the artifact to make it visible to Zach."
```

## 4 · `.claude/skills/project-board/migrate-board.mjs` — the migration protocol

**Every agent with a hand-built board migrates it with this, never by hand.** It parses the old
document, extracts embedded screenshots back into real files, **diffs the result, and refuses to pass
below 99%** — printing exactly which fragments did not make it.

```
node .claude/skills/project-board/migrate-board.mjs <old-board.html> <out-board.json> --owner <agent>
```

<Warning>
**This script exists because I got it wrong first.** Rebuilding this board from memory dropped ~130
items, 16 screenshots and every law/correction/finding section, and recovering it took ten separate
commands. Three of my own caps were eating content, each hiding the next: `paras[:6]` cut the fourteen
locked build decisions (they are paragraphs 5–14), a 2000-char truncation cut the **tails** where the
laws live, and a head-match `continue` skipped whole list bodies. **The script has no caps and it
measures the result** — one command, 99.8%.
</Warning>

```js
#!/usr/bin/env node
/**
 * migrate-board.mjs — convert an EXISTING hand-built board (HTML) into board.json, losing nothing.
 *
 * ⚑ THIS EXISTS BECAUSE I GOT IT WRONG FIRST. Migrating the Seller Engine board on 2026-08-04 I
 *   rebuilt the list FROM MEMORY instead of parsing the old document. The file was never deleted —
 *   but the published artifact lost ~130 items, 16 screenshots, and every law / correction / finding
 *   section. From Zach's side that is identical to deleting them. Recovering it took ten separate
 *   commands, and THREE OF MY OWN CAPS were eating content, each one hiding the next:
 *     · `paras[:6]`         — cut the fourteen locked build decisions, which are paragraphs 5–14
 *     · `note[:400]`/[:2000] — cut the TAILS, which is exactly where the laws live
 *     · a head-match `continue` — skipped entire list bodies whose title matched an item
 *   Every one of those is now impossible here: THIS SCRIPT HAS NO CAPS, and it MEASURES the result.
 *
 * THE PROTOCOL, in one line: PARSE, NEVER RETYPE — then DIFF and report the percentage.
 *
 * Usage:
 *   node migrate-board.mjs <old-board.html> <out-board.json> [--owner caleb] [--title "…"]
 *   node migrate-board.mjs <old-board.html> <out-board.json> --verify     (re-check completeness only)
 */
import { readFileSync, writeFileSync, existsSync, mkdirSync } from 'fs';
import { dirname, join, relative } from 'path';

// Same constant the generator uses (build-board.mjs). Declared here because receiptsDir must be written
// RELATIVE to the repo root — that is how build-board resolves it back.
const ROOT = '/Users/zachspradling/Code/BossLoop-Gold';

const [, , SRC, OUT, ...rest] = process.argv;
if (!SRC || !OUT) {
  console.error('usage: migrate-board.mjs <old-board.html> <out-board.json> [--owner x] [--title "…"]');
  process.exit(1);
}
const arg = (k, d) => { const i = rest.indexOf(k); return i >= 0 ? rest[i + 1] : d; };
const VERIFY_ONLY = rest.includes('--verify');

const raw = readFileSync(SRC, 'utf8');
const ent = (s) => s.replace(/&amp;/g, '&').replace(/&lt;/g, '<').replace(/&gt;/g, '>')
  .replace(/&quot;/g, '"').replace(/&#39;/g, "'").replace(/&nbsp;/g, ' ')
  .replace(/&mdash;/g, '—').replace(/&middot;/g, '·').replace(/&rarr;/g, '→').replace(/&rsquo;/g, '’');
// Tags become a SPACE, not nothing — otherwise `<b>foo</b><code>bar</code>` becomes "foobar".
const txt = (t) => ent(String(t).replace(/<[^>]+>/g, ' ')).replace(/\s+/g, ' ').trim();

// ── 1 · ITEMS ────────────────────────────────────────────────────────────────────────────────────
// Both shapes: live checkboxes AND the "already shipped" marks older boards used.
const items = [];
const seen = new Set();
function pushItem(title, note, done, owner) {
  const t = title.replace(/^\d+\s*[·.)]\s*/, '').trim();   // old inline numbers die here — see below
  if (!t || t.length < 4) return;
  const k = t.toLowerCase().slice(0, 80);
  if (seen.has(k)) return;
  seen.add(k);
  items.push({ n: items.length + 1, status: done ? 'done' : 'future', title: t, ...(note ? { note } : {}), ...(owner ? { owner } : {}) });
}
for (const m of raw.matchAll(/<li[^>]*>([\s\S]*?)<\/li>/g)) {
  const body = m[1];
  const done = /<input[^>]*checked/.test(body) || /class="was"/.test(body);
  const head = txt(body.split(/<small/)[0]);
  const full = txt(body);
  // NO TRUNCATION. The laws live in the tail.
  const note = full.slice(head.length).replace(/^[\s·—-]+/, '') || null;
  const own = /class="own own-(\w+)"/.exec(body)?.[1] ?? null;
  pushItem(head, note, done, own);
}

// ── 2 · THE RECORD — every heading and EVERYTHING under it. No caps. ─────────────────────────────
const heads = [...raw.matchAll(/<h([234])[^>]*>([\s\S]*?)<\/h\1>/g)]
  .map((m) => ({ at: m.index, end: m.index + m[0].length, level: +m[1], title: txt(m[2]) }));
const itemTitles = new Set(items.map((i) => i.title.toLowerCase().slice(0, 60)));
const sections = [];
heads.forEach((h, i) => {
  const body = raw.slice(h.end, heads[i + 1]?.at ?? raw.length);
  const paras = [...body.matchAll(/<p[^>]*>([\s\S]*?)<\/p>/g)].map((m) => txt(m[1])).filter((p) => p.length > 40);
  const lis = [...body.matchAll(/<li[^>]*>([\s\S]*?)<\/li>/g)].map((m) => txt(m[1]))
    .filter((l) => l.length > 40 && !itemTitles.has(l.toLowerCase().slice(0, 60)));
  const rows = [...body.matchAll(/<tr[^>]*>([\s\S]*?)<\/tr>/g)]
    .map((m) => [...m[1].matchAll(/<t[dh][^>]*>([\s\S]*?)<\/t[dh]>/g)].map((c) => txt(c[1])))
    .filter((r) => r.some((c) => c.length > 1));
  if (!paras.length && !lis.length && !rows.length) return;
  sections.push({ level: h.level, title: h.title, paras: [...paras, ...lis], rows });
});
// keep the richest copy of any repeated heading
const best = new Map();
for (const s of sections) {
  const k = s.title.slice(0, 80);
  if (!best.has(k) || JSON.stringify(s).length > JSON.stringify(best.get(k)).length) best.set(k, s);
}

// ── 3 · IMAGES — data URIs back out to real files. ⚑ AND YOU MUST LOOK AT THEM. ─────────────────
// I binned a competitor's MOBILE reference shot TWICE by pattern-matching its caption instead of
// opening it. An image with no caption is not a duplicate; it is an image with no caption.
// ⚑ AND THE COMPLETENESS GATE MUST COUNT THEM. Zach, 2026-08-04, reading a board this script had
//   just reported at 100.0%: "there's no reference — it doesn't actually give me the wireframe."
//   The gate was measuring TEXT FRAGMENTS. Images are not text fragments, so "100% preserved" was
//   perfectly compatible with losing every picture on the page — the check answered "did the prose
//   survive?" while I reported it as "did the artifact survive?" That is the green-signal failure
//   (.claude/lessons/every-tool-answers-a-narrower-question.md) inside my own verification tool,
//   written the same afternoon I helped document it. Images are now counted and reported separately,
//   and an unresolvable one is named rather than silently skipped.
const imgDir = join(dirname(OUT), 'recovered');
const shots = [];
// Every <img> in the source, by kind — so the report can say "12 images, 12 carried" and mean it.
const allImgs = [...raw.matchAll(/<img\b[^>]*\bsrc="([^"]+)"/g)].map((m) => m[1]);
const externalImgs = allImgs.filter((s) => !s.startsWith('data:'));
[...raw.matchAll(/<img src="data:image\/(\w+);base64,([^"]{500,})"/g)].forEach((m, i) => {
  if (VERIFY_ONLY) return;
  mkdirSync(imgDir, { recursive: true });
  const file = `recovered/legacy-${i + 1}.${m[1] === 'jpeg' ? 'jpg' : m[1]}`;
  writeFileSync(join(dirname(OUT), file), Buffer.from(m[2], 'base64'));
  const pre = raw.slice(Math.max(0, m.index - 1400), m.index);
  const h4 = [...pre.matchAll(/<h4[^>]*>([\s\S]*?)<\/h4>/g)].pop();
  shots.push({ file, title: h4 ? txt(h4[1]) : `Recovered image ${i + 1}`, caption: '', review: 'OPEN THIS AND WRITE ITS CAPTION — do not guess from surrounding text' });
});

// ── 4 · THE COMPLETENESS DIFF — the whole point. Claiming is not measuring. ──────────────────────
function completeness(boardJson) {
  // ⚑ THE HAYSTACK IS THE TEXT, NEVER JSON.stringify. Escaped quotes (\") mean any fragment
  //   containing a " can never match, which reported a false 69.6% on a migration that was actually
  //   fine. A verification gate that under-reports is worse than none — it sends you hunting for
  //   content that is already there.
  const walk = (v) => typeof v === 'string' ? v : Array.isArray(v) ? v.map(walk).join(' ')
    : v && typeof v === 'object' ? Object.values(v).map(walk).join(' ') : '';
  // ⚑ RECEIPTS COUNT AS CARRIED. They live in receipts/manifest.json, NOT in board.json, so a check
  //   that only looks at the board reports a receipt's own prose as "lost" when it is sitting right
  //   there in the audit band. Same class of error as the JSON.stringify haystack: the content was
  //   never missing, the measurement was.
  // ⚑ CHECK BOTH MANIFEST LOCATIONS. The generator reads <receiptsDir>/manifest.json; this script used
  //   to look ONLY in <board-dir>/receipts/manifest.json. When those disagree the diff counts a
  //   receipt's own prose as LOST and the gate under-reports — the exact "measurement was wrong, not
  //   the content" failure this file warns about two lines down. Union of both, never one guess.
  const rmanCandidates = [join(dirname(OUT), 'manifest.json'), join(dirname(OUT), 'receipts', 'manifest.json')];
  const rman = rmanCandidates.find((c) => existsSync(c)) ?? rmanCandidates[1];
  // ⚑ COMPARE NORMALISED, NOT EXACT. Inline tags and entities make the same sentence differ by
  //   whitespace between two documents ("2&ndash;9" vs "2–9", "source='PCSOI'" vs "source= 'PCSOI'").
  //   Exact substring matching reported ~100 false losses. Strip to letters and digits and the
  //   comparison measures CONTENT rather than markup.
  //   ⚑ AND STRIP TAGS FROM THE HAYSTACK TOO — receipts store HTML, so <code>hl_leads</code>
  //     normalises to "codehlleadscode" and never matches the plain "hlleads" from the old board.
  const norm = (x) => txt(x).toLowerCase().replace(/[^a-z0-9]+/g, '');
  const hay = norm(walk(boardJson) + (existsSync(rman) ? ' ' + walk(JSON.parse(readFileSync(rman, 'utf8'))) : ''));
  let total = 0, missing = [];
  for (const re of [/<p[^>]*>([\s\S]*?)<\/p>/g, /<li[^>]*>([\s\S]*?)<\/li>/g, /<t[dh][^>]*>([\s\S]*?)<\/t[dh]>/g]) {
    for (const m of raw.matchAll(re)) {
      const t = txt(m[1]);
      if (t.length < 45) continue;
      total++;
      const sig = norm(t).slice(0, 70);
      if (sig.length > 20 && !hay.includes(sig)) missing.push(t);
    }
  }
  return { total, missing };
}

const board = existsSync(OUT) && VERIFY_ONLY ? JSON.parse(readFileSync(OUT, 'utf8')) : {
  title: arg('--title', 'Migrated board'),
  owner: arg('--owner', 'caleb'),
  updated: new Date().toISOString().slice(0, 10),
  _law: 'THE NUMBER IS PERMANENT FROM THIS MIGRATION FORWARD. Numbers were assigned ONCE here and never change again; items MOVE into the active section and back, they are never renumbered.',
  // ⚑ POINT THE GENERATOR AT THE IMAGES WE JUST EXTRACTED, OR EVERY ONE OF THEM PUBLISHES BLANK.
  //   This script writes recovered images to <board-dir>/recovered/, but build-board.mjs resolves a
  //   shot path against RDIR, which DEFAULTS to .claude/reports/receipts. Two paths for one concept,
  //   and they never met — so a migrated board rendered every screenshot as nothing while the build
  //   printed a warning per image and still EXITED 0. Adam hit exactly this on 2026-08-04: 45 real
  //   receipts, all invisible, and the only signal was a warning line above a green success message.
  //   Setting it here means the board that comes out of a migration renders its own evidence.
  receiptsDir: relative(ROOT, dirname(OUT)),
  active: { title: 'Nothing active yet', prd: ['Name the items to work and pull them up.'], items: [] },
  items,
  record: { title: 'The record — the law, the corrections, and the findings', lede: 'Recovered from the pre-migration board: everything that was NOT a checklist item and NOT a receipt. None of it is a task; all of it is the reasoning behind the tasks, which is the part that gets rebuilt wrong when it goes missing.', sections: [...best.values()] },
  reference: { title: 'Reference & wireframes', lede: 'Sub-artifacts this board points at.', wireframes: [], shots },
};

const { total, missing } = completeness(board);
const pct = total ? ((total - missing.length) / total * 100).toFixed(1) : '100.0';

if (!VERIFY_ONLY) writeFileSync(OUT, JSON.stringify(board, null, 2));
console.log(`\n${VERIFY_ONLY ? 'VERIFY' : 'MIGRATED'} ${SRC}`);
console.log(`  items ${board.items.length} · record sections ${board.record.sections.length} · images ${board.reference.shots.length}`);
console.log(`  COMPLETENESS (text): ${total} fragments · ${total - missing.length} carried · ${missing.length} missing → ${pct}%`);
// ⚑ REPORTED SEPARATELY AND ALWAYS, because a single blended percentage is how a lost picture hides
//   behind carried prose. Two questions, two numbers — never one number answering the narrower one.
const imgCarried = board.reference.shots.length;
console.log(`  COMPLETENESS (images): ${allImgs.length} in source · ${imgCarried} carried` +
            (externalImgs.length ? ` · ${externalImgs.length} EXTERNAL (not embedded — see below)` : ''));
if (externalImgs.length) {
  console.log(`\n  ⚠ ${externalImgs.length} IMAGE(S) ARE LINKS, NOT DATA — this script can only recover embedded ones.`);
  externalImgs.slice(0, 8).forEach((s) => console.log(`    ↗ ${s.slice(0, 110)}`));
  console.log(`    → save each one into ${relative(ROOT, imgDir)} yourself and add it to reference.shots,`);
  console.log(`      or the migrated board will be missing pictures the old one showed.`);
}
if (allImgs.length && !imgCarried) {
  console.log(`\n  🔴 THE SOURCE HAD ${allImgs.length} IMAGE(S) AND THE MIGRATED BOARD HAS NONE.`);
  console.log(`     A text score of ${pct}% says nothing about this — do not read it as "nothing was lost."`);
}
// A board that NAMES a wireframe in its prose but carries no wireframe entry is the exact thing Zach
// hit: the band promises a picture and delivers a heading. Say it here, at migration time.
if (/wireframe/i.test(raw) && !(board.reference.wireframes ?? []).length) {
  console.log(`\n  ⚠ THE SOURCE TALKS ABOUT A WIREFRAME AND reference.wireframes IS EMPTY.`);
  console.log(`     Either shoot it   → .claude/skills/project-board/shoot-wireframe.mjs <file.html> --out <dir>`);
  console.log(`     or declare the gap → set "gap" on the entry naming the item that will fix it.`);
  console.log(`     What you must NOT do is leave the band promising a wireframe it cannot show.`);
}
if (missing.length) {
  console.log(`\n  ⚠ STILL MISSING — read these and decide, do NOT assume they are noise:`);
  missing.slice(0, 12).forEach((m) => console.log(`    ✗ ${m.slice(0, 108)}`));
  writeFileSync(OUT.replace(/\.json$/, '.missing.txt'), missing.join('\n'));
  console.log(`  → all ${missing.length} written to ${OUT.replace(/\.json$/, '.missing.txt')}`);
}
if (+pct < 99) {
  console.log(`\n  ⛔ BELOW 99% — DO NOT PUBLISH YET. Read the missing list and fold it in.`);
  process.exit(2);
}
console.log(`\n  ✅ ${pct}% — keep the ORIGINAL file, never delete it. Then: open every recovered image and caption it.`);
```

## 5 · `board.json` — the data contract

`status` is `done | active | future`. Nothing else.

```json
{
  "title": "The Seller Engine — Master Board",
  "owner": "caleb",
  "updated": "2026-08-04",
  "active": {
    "title": "what this batch is",
    "prd": ["the reasoning, one paragraph per point — covering EVERY item below"],
    "items": [209, 210, 211]
  },
  "items": [
    { "n": 209, "status": "active", "title": "...", "note": "...", "prd": "how this one gets done" },
    { "n": 208, "status": "done", "date": "2026-08-04", "title": "...", "receipt": "208" },
    { "n": 214, "status": "future", "title": "...", "note": "why it is parked" }
  ],
  "record":    { "title": "...", "lede": "...", "sections": [{ "level": 2, "title": "...", "paras": [], "rows": [] }] },
  "reference": { "title": "...", "lede": "...", "wireframes": [], "shots": [] }
}
```

| Field | Meaning |
|---|---|
| `n` | **permanent.** Assigned once, never changed, never renumbered. |
| `status` | `done` · `active` · `future` |
| `date` | stamped when it is completed |
| `note` | the correction, the finding, the reason — kept visible on purpose |
| `prd` | how THIS item gets done. Required while it is in the active section. |
| `receipt` | the audit id in `receipts/manifest.json` |

---

# The laws this encodes

## THE NUMBER IS PERMANENT

Assigned once, never changed. New work appends at the end. Re-prioritising does **not** renumber.
Gaps are fine; renumbering is not.

<Warning>
**This REVERSES an older law on this page** that derived numbers from DOM position and re-stamped them
on every reorder. A number whose meaning silently changes when something is inserted above it is not
an identifier — it is a coincidence.
</Warning>

## MIGRATE, NEVER RETYPE

When restructuring a board, **parse the old document and diff the result** — then report the percentage
of fragments carried across. Rebuilding from memory silently drops the *reasoning*, which is the half
nobody notices is gone until they need it.

<Info>
This law was earned: rebuilding this very board from memory dropped ~130 items, 16 screenshots, and
every law/correction/finding section. The recovery ran at 99.4% only because it was done by parsing
and diffing rather than retyping.
</Info>

## THE AUDIT IS THE EVIDENCE

> Compiling is not evidence. Typechecking is not evidence. A passing gate is not evidence.

Ten fields, every one filled honestly, or the item is not done. **Field 8** (schema-lock) is the one
people skip — a kind can be in the catalog and still have its writes rejected silently because it was
never seated; *presence is not writability*, so probe it and roll back. **Field 10** (reuse check) is
the anti-drift field — most duplicate components exist because nobody wrote that line down.

## NEVER FAKE A CONTROL

A button that writes nothing must say so on its face. A wireframe that hides what does not exist is
how we ship a button that goes nowhere.
