**The disease: DISTRIBUTED SEMANTIC AUTHORITY — one state, many machines.** There is no single authoritative
representation of what is happening right now; application state is reconstructed from language and from
presentation artefacts after the fact.

**The sentence that frames the fix:** *"LLM + tools is not the mistake. LLM as the application kernel is the
mistake."* And the rule for every new feature: **"Models may propose. Code must commit."**

**The inversion:**
```
today:   language → infer state → search for reality → model/tool improvisation → UI
target:  authoritative state → compute reality → perform allowed work → model communicates it → UI commits it
```

## 4a · W3's HEADLINE FINDINGS (delivered 2026-09-12 ~01:40Z, evidence in the document)
**45 deciders on a single webchat turn**, in execution order with file:line. Only **8 are model decisions, and
only 2 of those are the model's proper job** — four are a model repairing a model, one is a model authoring pill
buttons the registry already enumerates, one is a classifier the server could read off the transcript it holds.
That is the disease measured on one turn.

**22 twins** — decisions made in more than one place. The new load-bearing ones: three simultaneous readings of
"which money question is next"; **four state vocabularies (9 + 14 + 6 + 14 values) colliding on one wire field
`state`**; and the webchat road never calling the identity authority at all.

**THREE P0s, carded:**
1. **A county cannot stay a county** (card 24be990a). `search_homes` has no county parameter, so a county query
   becomes a model-written city list: the page cited 1,962 while the tool counted 1,875 under a different
   fingerprint, and she spoke the page's number. Every rule passed.
2. **A signed token is read around** (card 5b2992a1). `route.ts:1879` discards a token that passed
   `timingSafeEqual` when `body.reopened` is set; `:1053` reads the same token as a raw string to flip the
   funnel's next beat. A signature a sibling line reads around is not a signature.
3. **A second fact writer** (card 0550e5b2). `extract-context.ts:1325` writes `hl_lead_facts` directly from 15
   live sites including the FUB import and the memory pipeline, bypassing `assertFact`'s evidence discipline —
   the class of defect #257.404 was signed over.

**Two findings that reframe the build:** the deterministic tool runner ALREADY EXISTS and is switched off
(`research-runner.ts:71-77` — four read tools run by plan, no model in the selection loop, behind
`MYLI_RESEARCH_LOOP=1`); and `agent-tools.ts:714-724` is a regex that convicts the model AFTER a wrong tool
call and names the tool it should have used — if a regex can convict, it can dispatch.

**Also measured:** 57 live sites on manifest-forbidden roads across 5 authorities (the cage is green because its
floor was seeded at the measured number, not because the roads are closed); 52 callable tools; the web prompt at
9,168 of 9,500 characters; the CRM prompt assembling 69,975.

### **THE VERDICT: YES — BUILD FROM THIS MONDAY.** The migration PROGRAM begins; a big-bang cutover is refused.
> *"You have enough evidence to stop diagnosing and start changing the system. More architecture work tonight is
> more likely to reduce clarity than increase it."*

**His reason is not the volume.** Not 27 modules, 65 findings, 101 rules or 1,361 lines of order:
> *"The audit demonstrated that it can discover that the audit itself is wrong."*

### THE THREE SENTENCES A MONDAY DESK NEEDS
1. **THIS IS A RETIREMENT PROGRAM, NOT AN IMPLEMENTATION ROADMAP.** Every step has two finishes: activation AND
   extinction. *"The unit of progress cannot be 'the new thing works.' It has to be: the new authority works, and
   the competing authority is NO LONGER CAPABLE of making that decision."* **Rollback may restore the old
   architecture; compatibility may not preserve both indefinitely.**
2. **THE EXECUTIVE METRIC IS: HOW MANY COMPETING AUTHORITIES REMAIN.** *"If a migration week ships substantial work
   and that number stays flat, you did not migrate. You added architecture."* It starts at **65 of 90 semantic
   questions with more than one answerer**, and one person needs the standing to refuse a preserved fallback —
   *"they need permission to make deletion win over convenience."*
3. **THE FAILURE MODE IS ACCOMMODATION, NOT ENGINEERING.** *"Nobody will announce that the migration failed. They
   will call it 'hybrid.'"*

### THE SENTENCE FOR THE BOARD
> **"We are not finished when the new road exists. We are finished when there is only ONE road."**

### ⚠ SIX PLACES HE SAYS WE DRIFTED — read before spawning anything
1. ⭐ **We treated code evidence as proof of product behaviour** — and the 390px walk proved it, replacing an
   assistant-parser diagnosis with a ROUTING one (F64). **His order: downgrade every remaining finding whose causal
   chain was INFERRED rather than OBSERVED — do not delete it, mark the rank** (observed failure > demonstrated
   mechanism > suspicious mechanism > inferred failure) **and apply it retroactively where it changes priority.**
2. **"One authority" is not "one component."** The forbidden thing is multiple components independently ENTITLED to
   decide one fact. *"Guard against turning authority consolidation into a central god-service."*
3. **Verification integrity is a fifth AUDIT class, not a fifth RUNTIME authority.**
4. **The epistemic type must not become a universal Cartesian state machine** — *"the goal is to prevent coercion,
   not to maximise the number of states."*
5. **"Myli's questions are the action row" must not become "the model has execution authority."** She selects among
   the legal offers and emits them structurally; mentioning an action never grants permission to perform it.
6. **The sold-price lesson is not "hard-code anything important."** *"Enforce consequences. Don't compile
   personality into middleware."* And a warning on our own output: **101 rules and 52 refusals approach the point
   where the specification becomes a second implementation.** Not every numbered sentence becomes an abstraction.

### ⭐ THE AUDIT HE WOULD ADD TO HIS OWN CHARTER — REFERENTIAL IDENTITY (carded 6ea508dd)
*"Can HouseLoop prove that every subsystem is talking about the same real-world object?"* Trace what the customer
physically touches — pin, card, lot, saved home, URL, notification, text link, tour button — through tap → route →
resolver → page model → Myli context → tool input → mutation → analytics, asserting the same CANONICAL IDENTITY at
every boundary. **Not the same street number, not the same normalised string, not the same slug, not a best match.**
Then the pathological cases: units, multiple lots at one address, multiple MLS records on one parcel, relists, new
construction, duplicate addresses across municipalities, and links produced before an inventory refresh.
> *"Myli can be PERFECTLY CORRECT about the object she was given while being CATASTROPHICALLY WRONG about the
> object the customer believes they are discussing. Your semantic authority architecture cannot save you if
> referential identity was already corrupted upstream."*
