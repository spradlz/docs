## 1 · THE DIAGNOSIS (ChatGPT, filed verbatim)
- `.claude/reports/myli-os/SECOND-OPINION-architecture-master-2026-09-12.md`
- `.claude/reports/myli-os/SECOND-OPINION-architecture-crm-voice-2026-09-12.md`

**The disease: DISTRIBUTED SEMANTIC AUTHORITY — one state, many machines.** There is no single authoritative
representation of what is happening right now; application state is reconstructed from language and from
presentation artefacts after the fact.

**The sentence that frames the fix:** *"LLM + tools is not the mistake. LLM as the application kernel is the
mistake."* And the rule for every new feature: **"Models may propose. Code must commit."**

**The inversion:**
```
today:   language → infer state → search for reality → model/tool improvisation → UI
target:  authoritative state → compute reality → perform allowed work → model communicates it → UI commits it
```

## 2 · THE CHARTER (ChatGPT, verbatim, 1,390 lines)
`docs/myli-audit/00-charter.md` — the six work packages, the questions each must answer, the exact registry
schemas, the master PRD's table of contents, the implementation order, the cutover and what to measure.

**The three artefacts, and the audit is complete only when they agree:**
1. **Semantic Authority Matrix** — every business question the product answers, and who answers it today.
2. **System Asset Registry** — every table, view, projection, stream, module, tool, prompt, state machine,
   capability, component, cache, worker and writer that participates.
3. **Execution Trace Ledger** — evidence of what actually happens on real journeys.

**His method correction, which reshaped our plan:** do not map components and then ask what they do — **map every
semantic question first, then attach everything that currently tries to answer it.**

**His evidence standard, binding on every worker:** *"'Search state seems duplicated' is not a finding."* A finding
names the field, every place that can determine it, which wins today, and whether that precedence is explicit or
accidental.

**The end state is NOT one database.** Web and CRM stay separate. One semantic authority per piece of reality.
