## THE ANATOMY OF A CARD (every card, no exceptions)
`[ ACTOR HEADSHOT ] · Actor name + specific sentence · [ kind ICON ] · SPECIFIC SUBTEXT · (house photo if a home card)`

1. **ACTOR HEADSHOT** — the real avatar of who did it:
   - Human agent (Zach Spradling, any agent) → the agent's real headshot photo.
   - **Myli (AI)** → Caleb's Apple **Pixar headshot** (`.claude/reports/homeowner-dashboard-design/myli-avatar-pixar.png`)
     WITH a small **3-star AI badge sticking out of the bottom-right of her circle** (identifies AI). Verbatim Zach.
   - Lead → initials/photo. System/job → a small system glyph.
2. **REAL KIND ICON** — the actual glyph for the action (never a grey empty circle on the card face). Secondary
   to the headshot (a badge beside the sentence / on the avatar).
3. **SPECIFIC SUBTEXT** (required on every card) — the specifics of THAT activity, e.g.
   - created an email campaign → "Spring Listings Blast · to 1,240 past clients"
   - saved a property → "7928 Halsey St, Lenexa KS · $285,000"
   - created a saved search → "Overland Park · 3bd · under $250k"
   - status change → "Pending → In Progress"
   - Myli updated her context → "about Brent Morris · noted 0–3 mo timeline + $450k budget"

## ⭐ NO TRUNCATION — ANYWHERE (Zach 8/12)

No ellipsis, no cut-off. Wrap, don't truncate.

## MYLI'S REACTION COLUMN (`myli_reaction`, mig 1312, Zach #257.301 on 2026-09-07)

Zach: "myli needs to be present on every activity card, myli should be doing something on the right … doing
something for every single row in the activity catalog, because she knows everything."

Every catalog row carries **`myli_reaction`**, the DETERMINISTIC thing Myli files beside a row of that kind
(data on the catalog, never a code map). The closed set, held by a CHECK:

| value | kinds seeded | what she files beside the card (zero model calls) |
|---|---|---|
| `note_home_viewed` | property_viewed | a right-rail note "noted: viewed 17329 Larsen St" + the LIST-SHAPED summary fact **Search Criteria · Homes viewed** ("12 homes viewed · latest …", deduped per home) |
| `fact_home_saved` | property_saved · property_liked · property_unsaved | "noted: saved … (houseloop.ai saved homes / Zillow favorites)" with the HLID and where, + **Search Criteria · Homes saved** (the current saved set, an unsave recomputes it) |
| `fact_search` | property_searched · saved_search_created · saved_search_edited · ai_searched (the lead's own) | "noted: searched Overland Park · 4+ bd · up to $550,000" + **Search Criteria · Recent searches** |
| `fact_stage_move` | stage_changed (any actor) | "noted: stage moved from New Lead to Appointment Set" + **Logistics & Process · Pipeline stage** ("Appointment Set (from New Lead)", superseded on every move) |
| `act_record_edit` (mig 1313, #257.303) | lead_edited | when a MACHINE changed the record (a backfill, a pour, a sync): the card itself is filed as **Myli** (`myliRecordEditor()`, her seat and headshot) and the right cell carries the structured act: the tool (set_relationship_status · update_contact), the field, from → to, and the reason (`meta.because`). No memory row: the field is state on `hl_leads`. A human's own edit gets no structure from her. |
| `memory_pass` | sms_received · imessage_received · email_received · zillow_message_received · website_chat_received · phone_call_received · voicemail_received | the model memory pass (`myli-memory-pipeline`) is the reaction, as before |
| `none` | everything else (292 rows), explicitly | nothing deterministic; a decision, never a gap |

**How it runs.** `logActivity` (the one activity writer) calls `lib/ai/myli-reactions.ts` after the row commits,
fire-and-forget: the fact goes through the one fact writer as source `derived` with provenance = the card
(`evidence_activity_id`), and ONE `ai_fact_captured` act is filed per card (actor Myli, `actor_type ai_agent`,
`reason_evidence_id` = the card, `tool` = the reaction key, `run_id` when a run is open). The trace reader
admits it by the stamp and the dual lane folds it into the card's own cell; nothing lands in the middle
column (rail law #257.300). A refused reaction is a `myli_reaction_drop` run-log row, never silence.

**What it deliberately does not do.** Rows older than seven days are history (the FUB Zillow tape pours
months-old rows) and wait for a backfill; the lead-act reactions fire only on the lead's own rows (Myli's own
search is already her act); the four derived slots are invisible to the extraction prompt (`derivedSlots` in
`fact-taxonomy.ts`) so a model can never overwrite a count with prose.

**The backfill.** `myli-reaction-backfill` (Inngest, event `houseloop/myli-reaction.backfill`, dashboard Invoke,
dry by default, `{"dryRun": false}` applies) replays the last 30 days through the SAME writer with the window
widened, per lead in occurrence order so every note's count is as of its card; a card that already carries its
act is skipped, so a re-run writes nothing. Every act it writes carries `meta.backfill_run` = the run id, the
reversal handle. Older than 30 days stays forward-only.

**The cage.** `node tools/one-brain/myli-reaction-census.mjs --cage` (pre-push): a catalog row with
`myli_reaction` NULL is RED against a shrink-only floor born at 0. `--selftest` red-proves it; the bare run
measures rows vs anchored acts, 30 days, live. Harness: `npm run test:myli-reactions` (38 assertions, real
writer, the Zach Test lead). Receipt: `.claude/reports/grinder/myli-reacts-to-every-row/RECEIPT.md`.
